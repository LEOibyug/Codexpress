# Codexpress management API v1

The helper starts with `codexpress-gateway --state-dir PATH --port PORT`. It creates PATH/control.sock (0600, parent 0700), listens on 127.0.0.1:PORT, and loads/generates PATH/gateway-key (0600). Swift discovers the local key from this file, but never upstream credentials from files. Metadata defaults to ~/Library/Application Support/Codexpress; tests use explicit isolated paths.

Unix socket: one JSON line per connection, max 8 MiB, then one JSON response line. Request `{ "id": "uuid", "op": "status", "payload": {} }`; response `{ "id": "uuid", "ok": true, "data": {}, "error": null }`. Errors use safe human-readable strings with no raw upstream body, URL query secrets or credentials. All timestamps are UTC Unix seconds. IDs are opaque nonempty strings.

Source JSON metadata:
```json
{"id":"uuid","name":"My API","kind":"api","base_url":"https://example.com/v1","enabled":true,"priority":0,"proxy":{"mode":"direct","url":null},"models":[],"account_id":null}
```
`kind`: `api` or `official`. proxy.mode: `direct` or `explicit`; explicit URL accepts http/https/socks5/socks5h. Official sources require explicit proxy. Empty models means user allows the requested model; no model remapping. Source `secret` is included ONLY in transient sync IPC (official credentials are sent on helper initialization, empty when helper already owns the source), never status or metadata files: API `{ "api_key":"..." }`; official `{ "access_token":"...", "refresh_token":"...", "id_token":"...", "expires_at":123, "account_id":"..." }`. Official base defaults to `https://chatgpt.com/backend-api/codex`. Local HTTP base URLs are allowed for user-configured/local sources; official auth/usage hosts in production remain fixed.

Swift metadata may also include optional `automaticModelDiscovery:bool`. Absent values preserve nonempty legacy manual allowlists; empty legacy lists opt into discovery. Successful automatic fetches set it to true and cache IDs in `models`; failures retain existing IDs. The helper ignores the flag and routes using `models`. New UI proxy input is a local port (1–65535), serialized as `http://127.0.0.1:PORT`; existing local proxy schemes and untouched remote URLs remain compatible.

## Operations

- `status` -> `{running:true,port:PORT,base_url:"http://127.0.0.1:PORT/v1",mode:"auto",fixed_source_id:null,sources:[SourceStatus],inflight:0,connection_mode:"unmanaged"|"gateway"|"official"|"unknown"}`. Connection mode reads only the app-owned attachment snapshot, reports the last applied connection setting, and does not claim native login success or read Codex auth/config. SourceStatus is metadata plus `health` ("ready"/"cooldown"/"exhausted"/"auth_required"/"proxy_error"), `cooldown_until` (nullable), `last_error` nullable safe string, `quota` nullable object, `credits` nullable object. No secret.
- `sync` payload `{sources:[SourceWithSecret],mode:"auto"|"fixed",fixed_source_id:null|string}` replaces live source list after full validation, preserving health by stable ID when credentials/network policy did not change. Returns `{updated_secrets:[{source_id,secret}]}` for newer official token generations, empty normally. Production helper is the sole writer of official Keychain entries, and persists rotations before publishing runtime tokens. Swift reads durable Keychain values and updates identity metadata only; it never writes an official IPC token snapshot back to Keychain; `sync` response is also returned by `credentials` (below).
- `credentials` -> `{updated_secrets:[{source_id,secret}]}` over owner-only socket, used before persisting/altering official sources. Does not return API keys.
- `models.list` payload `{source_id:"uuid"}` for a saved source, or `{source:SourceWithSecret}` for an unsaved API draft -> `{models:["model-id"]}`. Drafts cannot supply official tokens. Saved official sources use helper-owned refreshed credentials, fixed official base plus `/models?client_version=0.162.1`, account header and mandatory explicit proxy. API calls use sibling `/models` when base ends in `/responses`, otherwise append `/models`. Uses source transport policy, 25-second fetch timeout, no redirect, 4 MiB response limit, at most 10,000 entries, nonempty IDs at most 256 bytes without whitespace/control characters. Accepts `data[].id`, `models[].slug`/`id`, or a string array; returns sorted distinct IDs. Empty/malformed/error responses fail with safe diagnostics and no raw upstream body. This operation never changes source routing, stores draft credentials or records generation usage; Swift applies successful caches only while the source configuration is still current.
- `usage` payload `{days:30,source_id?:string|null}` -> `{rows:[SourceUsage],recent:[AttemptUsage],inflight,fetched_at}`. `rows` always summarizes all sources for comparison; optional source ID filters active/recent attempts before the latest-200 limit. Active attempts precede completed history. Swift polls every second while the usage view is open, drops stale filter responses, and does not set global UI busy. Total=input+output; cached/reasoning are subsets, never added twice.

`SourceUsage` retains the original summary keys and adds `active_requests`, `estimated_requests`, `successes`, `total_latency_ms` (ended attempts only), `total_first_token_ms`/`first_token_samples`, `timed_output_tokens`/`total_generation_ms` (successful attempts with measured stream durations), `reasoning_output_tokens`, and `cached_reported_tokens`/`cached_reported_input_tokens` (matched explicit samples). Derive success rate from ended attempts and weighted TPS from timed output/duration, not an average of per-request rates.

`AttemptUsage` adds stable `attempt_id`, `active`, `first_token_latency_ms`, `generation_ms`, `output_tps` and `token_details` to original request/source/model/time/count fields. Status is connecting/streaming/success/failed/interrupted. `token_details` contains `input_estimated`, `output_estimated`, `output_available`, `cached_input_reported`, optional `cache_write_input_tokens`, `reasoning_output_tokens`, `reported_total_tokens`, and `stream_complete`. Missing fields remain null/unknown, reported zeros are valid. Input/output independently prefer explicit Responses usage; otherwise use observed text estimates (CJK roughly1 char/token, other text4 chars/token). Skip encrypted, image, audio and file payloads. Per-output-item deltas/snapshots merge without duplication; terminal output snapshots supersede observations. No guessed cache/reasoning values. Token fields are always numeric metadata; no text/body/header storage.

Header/connection attempts appear in memory immediately, stream observations publish at most every100ms except transitions/terminal events. Termination freezes timing before socket EOF. Attempt drop records exactly once and removes its active counterpart under the same SQLite/memory lock. Added nullable metadata column is migrated without replacing existing records. Legacy nonzero input/output/cache values remain visible; old zero/unknown counts are not promoted to explicit measurements, and legacy throughput stays unknown. Active attempts are transient across helper restarts; persisted ended records remain.
- `config.preview` payload `{codex_home:"/explicit/path",model_compaction:[{model:"model-id",auto_compact_token_limit:180000,context_window:300000}]}` -> `{before:"TOML",after:"TOML",attached:bool,model_limits:[{model,auto_compact_token_limit,context_window}],warning:"history/resume boundary"}`. The rules array defaults to empty; window is optional. Preview validates limits and generates metadata in memory, without writing Codex config or a catalog. Sensitive fields are redacted; numeric compaction limits remain visible. Never log the preview.
- `config.attach` / `config.restore` same payload -> `{attached:bool,message:"...",warning?:null|string}`. Attach can update rules on an existing connection. Nonempty rules manage root `model_catalog_json`, `model_auto_compact_token_limit`, `model_context_window` in addition to provider fields. Global overrides move to model metadata so per-model thresholds take effect. Immutable content-addressed catalogs live in state-dir/model-catalogs; prior user catalogs are never modified. Empty rules disable the overrides; restore reinstates the field values from when compaction management began, preserving later unrelated edits. External edits to managed fields reject updates/restores. Snapshot fields are backwards compatible with the first release. Both operations checkpoint configuration and file authentication before mutations; leaving official mode restores its saved gateway-mode auth files and retains the latest official-file session for the next entry. Legacy official snapshots without saved auth cannot reconstruct a lost key and return an explicit warning. No history modification. `config.restore.preview` is read-only conflict preflight. Swift performs these operations after graceful Codex exit and relaunches.
- `config.official.preview` payload `{codex_home:"/explicit/path"}` -> `{before:"redacted TOML",after:"redacted TOML",connection_mode:"official"}`. Read-only preflight. `config.official` same payload -> `{attached:true,connection_mode:"official"}`. Selects built-in `openai`, pins root `openai_base_url` to `https://chatgpt.com/backend-api/codex`, `chatgpt_base_url` to `https://chatgpt.com/backend-api/`, sets `forced_login_method="chatgpt"`, `respect_system_proxy=true`. Removes legacy `model_providers.openai`; other declared provider IDs temporarily become official-auth aliases so resumed chats cannot resolve a custom endpoint through the prior ID. Schema 3 snapshots capture the complete original providers table; schemas 1/2 remain readable. Attach/restore reinstates the original tables/fields while retaining unrelated edits and rejecting managed-field conflicts. Entering the mode checkpoints gateway auth; repeated clicks do not replace that checkpoint. Previously saved official-file auth is restored on later entries. Active profiles overriding connection/login reject the switch. Swift overrides desktop service URL environment variables, clears inherited API credentials/alternate app-server endpoints, and forces a fresh stdio server; it leaves proxy environment untouched. No real restart occurs merely from opening settings.
- `config.backups` payload `{codex_home}` -> `{backups:[{id,created_at,reason,has_auth,file_count}]}`. Lists only private backup metadata for the selected canonical home, never file/credential contents. Mutations create independent checkpoints containing `config.toml`, `auth.json`, `auth.json.bak`, adjacent `*.config.toml`, and attachment snapshot; absent files are recorded explicitly. Per-file limit 16 MiB, aggregate configuration/auth limit 32 MiB, at most 200 files. Directories 0700/files 0600, bounded no-follow reads, SHA-256 verification, concurrent-change check, atomic directory publication. `config.backup.preview` payload `{codex_home,backup_id}` verifies selection and current file accessibility. `config.backup.restore` same payload -> `{restored:true,recovery_backup_id}` checkpoints current state, restores exact selected config/auth/profile bytes and their presence/absence, restores attachment, and rolls back on ordinary write failure. History and other app Keychains are excluded. Swift quits/relaunches Codex around restore. Process crashes during multi-file replacement can be recovered from the before-restore checkpoint; no cross-file atomicity claim.
- `official.login.start` payload `{source_id:"uuid"}` -> `{flow_id:"uuid",auth_url:"https://auth.openai.com/...",callback_port:1455}`; source must already exist and have explicit proxy. Callback captures browser response and exchanges via that source client. Source is initially allowed with empty OAuth tokens only for login; not routable until valid.
- `official.login.complete` payload `{source_id,flow_id,callback_url:"http://localhost:1455/auth/callback?code=...&state=..."}` -> `{connected:true,secret:{...},account_id:"..."}`. A status poll via `official.login.status` `{source_id,flow_id}` returns `{state:"pending"|"complete"|"failed",secret:null|{...},error:null|string}`. Do not expose auth codes/state in logs. Strict state and source binding. The helper has already persisted the secret before reporting completion. UI reads the durable Keychain entry and only updates identity metadata; it must not persist the response secret.
- `official.refresh` payload `{source_id,include_credits?:bool}` -> `{quota:QuotaSnapshot,credits:CreditSnapshot}` updates status. `include_credits` defaults to true; false queries only usage and leaves the cached credit snapshot unchanged, including its timestamps/errors. Automatic Swift refresh attempts quota about every 30 seconds (foreground menu/source views use a 15-second freshness threshold), includes credits at most every 5 minutes, and deduplicates same-source queries. Manual refresh and reset-card preflight still query both. QuotaSnapshot `{plan_type:null|string,windows:[{name:"primary",used_percent:null|number,reset_at:null|number,window_seconds:null|number}],fetched_at:seconds,stale:bool,error:null|string}`. CreditSnapshot `{available_count:null|number,credits:[{id,title,status,expires_at:null|seconds}],fetched_at:seconds,stale:bool,error:null|string}`. Unknown is null, not 0. UI identifies weekly (604800 seconds) and short windows by duration, independently of primary/secondary order; additional model limits do not supply a missing main weekly value. Missing weekly data is shown as unknown.
- `official.credits.consume` payload `{source_id,credit_id,expected_account_id:"displayed-workspace-id",operation_id:"uuid",confirmed:true}` -> `{code:"reset"|"nothing_to_reset"|"no_credit"|"already_redeemed"|"unknown"|"pending_verification",windows_reset:null|number,quota:null|QuotaSnapshot,credits:null|CreditSnapshot}`. Bind IDs, validate card, stable operation ID, serialize, no source fallback. Store operation before POST; repeated operation returns previous/uncertain result without POST. Success refreshes data, never clears local usage. Uncertain result never automatically retries. Errors use `ok:false`.

## Rust internal integration interfaces

`model.rs` defines Source, ProxyPolicy, RoutingMode, SourceHealth, SourceRuntime, AppState. `AppState.sources: tokio::sync::RwLock<Vec<SourceRuntime>>`; runtime is clonable and contains source (including memory-only `secret: serde_json::Value`), health, cooldown_until, last_error, quota/credits as Value. `AppState.settings: RwLock<RoutingSettings>`, `AppState.bindings: Mutex<HashMap<String,String>>`, `AppState.usage: Arc<usage::UsageStore>`, `AppState.gateway_key: String`, `AppState.port:u16`, `AppState.state_dir:PathBuf`, `AppState.inflight:AtomicUsize`. `AppState.official_locks` is Mutex<HashMap<String,Arc<tokio::sync::Mutex<()>>>>. Constructor provided by root. Production injects credentials::CredentialStore backed by macOS Keychain; official install calls AppState::persist_credential before runtime publication. Test constructors may inject memory/failure stores. Official pending flows live in memory; durable reset operation records contain no token. Source::identity() is stable across same-account official refresh but changes with API key, upstream or official workspace. All binding reads/writes and invalidations lock sources before bindings, and in-flight responses verify captured identity.

`transport::client(source:&Source)->anyhow::Result<reqwest::Client>` creates an ephemeral-policy client with no automatic proxy discovery, explicit proxy if selected, no redirects, no automatic gzip/brotli decompression. All modules use it. Optional `official::ensure_access(state:&Arc<AppState>, source_id:&str)->anyhow::Result<Source>` returns fresh runtime source, serializing token refresh. Relay calls for official sources, otherwise reads runtime source.

`routing::candidates(state:&Arc<AppState>,model:&str,binding:Option<&str>)->Vec<Source>` snapshots eligible sources sorted priority. `routing::mark_failure(state,source_id,status:u16,retry_after:Option<u64>)` conservative health changes. `usage::UsageStore::open(path:&Path)->Result<Self>`; `record(UsageRecord)->Result<()>`; `summary(days:u32)->Result<Value>`. `UsageRecord` fields should be defined by usage owner and consumed by relay. `relay::router(state:Arc<AppState>)->axum::Router`.

Relay affinity recognizes current Codex `thread-id` (preferred, separate namespace), `session-id`, and legacy `x-session-id`/`session_id` headers or JSON session/conversation IDs. Portable history does not pin a source; opaque context may recover its origin from a known thread/session. A shared session header never recovers another thread's opaque history when a thread header is present. `x-codex-turn-state` values from successful HTTP headers are bound before returning response headers, including empty bodies; `response.metadata.headers` events accept the same header case-insensitively before yielding their bytes. Request and response tokens map to `turn:<SHA256>` keys, without a 512-byte response-ID limit; raw tokens remain unchanged on the wire and are not stored. Encrypted content is likewise represented only by a digest. Unknown server state and incompatible source identities continue to fail with 409. Bindings remain in memory and do not survive helper restart.

`official::handle(state:&Arc<AppState>,op:&str,payload:Value)->anyhow::Result<Value>`; `official::ensure_access` as above. No other module edits required by official task; ask root about shared changes. Config module receives state/paths and returns JSON to management dispatcher.
