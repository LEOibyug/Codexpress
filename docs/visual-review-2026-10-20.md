# 原生界面视觉优化

依据用户提供的设置页截图，统一设置、来源、路由、用量、来源编辑和菜单栏面板的视觉样式。

- 页面使用 25 点标题与简短副标题，详情内容最大宽度 820 点，统一 28 点页边距。
- 卡片采用 14 点连续圆角、18 点内边距、细描边和随系统切换的深浅色背景。
- 侧栏增加产品标识与运行状态，导航图标采用系统单色样式，选中和失焦状态由原生列表处理。
- 端口和开关靠右对齐；路径与模型 ID 使用等宽字体和统一输入框。模型规则按列对齐。
- 技术说明默认折叠，运行异常仍保留显式提示。保存设置、保存规则和预览／应用连接的动作分开表达，未更改时保存按钮停用。
- 官方额度采用自适应并排卡片，来源卡片、用量指标与最近请求使用相同的间距和表面样式。
- 设置窗口默认内容尺寸 960 × 780 点，最小窗口 860 × 650 点；较窄窗口及较长内容允许滚动。

视觉检查使用临时隔离预览进程，覆盖暗色 960 点、浅色 860 点、两条压缩规则、官方与 API 来源、模拟额度及路由空态。模拟来源／额度仅用于检查布局，未写入真实应用的来源文件或钥匙串。

手动检查发现路由空态导致 AppKit 最小高度推算膨胀。详情区域补充 600 点最小可读宽度，并使用原生空态容器，避免零宽度测量使说明文字逐字换行；修复后的最小高度为 620 点，侧栏和页面内容均完整可见。

检查：Swift 构建、现有 11 项 Swift 测试、release 应用打包与签名校验通过。没有新增布局单元测试。真实应用的来源编辑表单已打开并取消；没有保存模拟来源，也没有点击真实 Codex 目录的预览／接管。
