# 使用指南

主窗口的「工作台」包含概览、来源池、模型和用量；「配置」包含客户端接入和应用设置。侧栏底部显示当前网关端口，有新版时可直接进入更新设置。概览可快速跳转常用客户端，模型与来源编辑在固定操作区保存。

## 使用

从 [Releases](https://github.com/LEOibyug/Codexpress/releases/latest) 下载 DMG，打开后将 Codexpress 拖入「应用程序」。支持 Apple Silicon Mac，要求 macOS 14 或更新版本，无需安装开发工具。

当前版本使用临时签名，尚未经过 Apple 公证。首次打开若被系统拦截，请先尝试打开，再前往「系统设置 → 隐私与安全性」选择「仍要打开」。

从源码构建的应用位于 `dist/Codexpress.app`，可双击打开，或执行：

```sh
bash scripts/run.sh
```

首次启动会打开主窗口，之后常驻菜单栏。可以把应用移到 `/Applications`；应用与网关必须作为完整 `.app` 一起移动。

1. 在「来源池」添加来源：
   - **官方账号**：填写本地 Clash 的 HTTP／混合代理端口（例如 `7890`）或选择「系统代理」，点击「添加并登录」。
   - **OpenAI API Platform**：预设 `https://api.openai.com/v1`，自动获取文本／Responses 可用模型并过滤音频、图片与嵌入等非对话端点；新增模型默认停用，需在「模型」页勾选启用。
   - **Google AI Studio**：预设 `https://generativelanguage.googleapis.com/v1beta`，网关将 Gemini REST/SSE 协议转换为 Responses 接口（支持 Codex、OMP 和聊天客户端），新增模型同样默认停用。
   - **原生 Responses API**：填写自定义基址和密钥后自动获取或手动填写模型列表，默认强制直连。
2. 官方账号授权网页由系统浏览器打开；浏览器网络遵循浏览器设置，应用侧的令牌交换、刷新、模型获取、额度查询和生成均使用该源网络策略（可选「系统代理」或「指定代理」，不支持「强制直连」）。非官方来源默认「强制直连」（关闭系统代理和代理环境变量），也可切换为「系统代理」（不做代理干预，直接交由系统代理、环境变量或 TUN 路由处理）或按需「指定代理」。所有来源默认开启「在 cmux 中展示」，可在来源编辑页或更多操作菜单中关闭，用于仅在 cmux 的 Codexpress 插件列表中隐藏该来源，不影响模型路由。
3. 在「来源池」用箭头调整优先级，在「分配策略」中选择自动切换或固定来源。新对话从最高优先级的兼容来源开始尝试，连续对话默认保持 5 分钟来源粘性；失败或名额已满时依次尝试后续来源。指定代理失效不会悄悄直连。
4. 在「接入 → Codex」核对配置目录，点击「接入来源池」；已接入时点击「更新连接设置」。应用自动检查并备份配置、正常退出 Codex、更新连接后重新打开。需要审阅 TOML 时可选「查看高级预览」，不必先预览或重复确认。
5. 在 Codex 中新开会话验证连接。高级预览可为已有供应商选择原 API 来源，并确认同一账号和密钥。只有已确认的 ID 接入网关，旧上下文优先回原来源；未确认的连接保持原样，原定义保存供还原。

退出应用会停止网关，Codex 的本地连接保留。有请求正在进行时，菜单栏「退出」、⌘Q 等正常退出操作会先弹窗确认，默认选择「继续运行」；确认「仍然退出」后才停止网关。退出前无法获取活动状态时也会提示确认。仅关闭主窗口会继续在菜单栏运行。恢复原供应商可在「接入 → Codex」直接选择「恢复原连接」。已接管期间不能更改网关端口；恢复后修改端口、重启，再接入。端口输入旁的「应用端口」只保存该字段。

### 管理远端网关

点击主窗口侧栏顶部的「本地网关」或「远端网关」，选择「远端网关」。填写服务器的 HTTPS 根地址（不带 `/v1`）和**管理令牌**。连接成功后，令牌保存在 Mac 应用状态目录的 `remote-management.json`，不使用钥匙串，也不写入 `sources.json`。这是仅当前用户可读写的明文文件，请勿同步或分享。设备用于推理的 API Key 不能代替管理令牌。

**设置服务器来源：**打开「来源池 → 添加来源」，选择官方账号、Responses API、OpenAI API Platform 或 Google AI Studio。搜索、展开详情、编辑和调整优先级的入口与本地相同。保存表单后点击「提交修改」，服务器才会应用草稿。官方来源提交后可打开「登录与额度」，在浏览器完成授权，把回调地址提交给本次登录的服务器。上游 API 密钥只写不读。代理中的 `127.0.0.1` 指服务器，不是这台 Mac；更换 API 地址或代理须填写新密钥，官方来源换代理后须重新登录。

**从本机复制：**来源池中的「从本机导入」只把选中来源加入远端草稿。新来源默认停用；导入 API 密钥需单独勾选并确认目标。不会复制官方登录、代理、重置卡授权或历史。

**复制客户端的地址和 Key：**打开「接入」，首次点「签发密钥…」并确认，即可为这台 Mac 取得一把通用设备 Key。选择 Codex（`/v1`）、聊天客户端（`/chat/v1`）、图片生成（`/images/v1`）或 OMP（`/omp/v1`），点「复制地址」和「复制密钥」。切换入口只换 Base URL，不换 Key。密钥按服务器和设备隔离，保存在当前用户私有状态目录；再次打开应用仍可复制。撤销这把 Key 会同时停止它在四个推理入口的访问，不授予或改变管理权限。

给另一台设备签发时，在「已授权设备」中单独命名并交付 Key；其他设备已有的密钥不能从服务器找回。撤销按设备生效，不影响另一把 Key。不要把管理令牌或上游密钥填入推理客户端。

**集中修改远端设置：**来源池、模型和设置共用一份草稿。可以先调整来源顺序，再到模型页按供应商筛选并启停模型，最后在任一页点「提交修改」。切页和周期刷新不会提交；若服务器版本已变，须重新载入并核对后再编辑。切换网关不会带走草稿。登录时启动仅作用于这台 Mac；清空缓存仍需单独确认，确认后立即执行。

远端默认不保存原文、不授权自动用卡。手动使用须确认具体卡片；离线自动用卡须在此实例为指定官方账号明确开启。连接中断后先核对结果，不重复提交。旧版服务器（如 0.1.1）仍显示精简来源池编辑器，只能新增直连 Responses 来源；升级**服务器和反代白名单**才能使用完整管理功能。

选择「使用本地网关」会返回本机原有来源池，不复制任何来源、上游密钥或历史，也不改写本机 Codex 的连接。切到远端时，Mac 每 30 秒刷新一次；打开远端来源界面或菜单时立即刷新，无须等到下一轮。cmux 侧栏读取 Mac 的同一份快照，不另连服务器；远端缺失的余额、活动或额度数据不会按零展示，侧栏不对远端执行抢占或用卡。本机网关已在运行时不会因切换被停止；以远端模式启动 Mac 应用时无需启动本机网关。远端不通不会回落到本机。

远端菜单栏小窗按优先级预览最多四个来源，显示连接状态、更新时间及服务器已上报的运行指标。可从底部直接进入「接入」复制客户端配置。cmux 远端卡片保留快照时间和过期提示，不展示网关地址，也不提供远端操控。

**服务器控制面板：**面板后端在网关服务器上使用独立回环管理接口，不使用上述推理 Base URL 或设备 Key。启用新版服务后，默认入口是 `http://127.0.0.1:17868/panel/v1`，先用专用 Bearer 读取 `/status` 获取实例、配置修订号及可用操作。不要将面板令牌放入浏览器或给该端口配置公网反代。启用方式、统计查询和路由命令见[独立网关说明](https://github.com/LEOibyug/Codexpress_remote_gateway)。

从 Codexpress 0.8.37（内置 OMP 扩展 0.1.13）起，本机 OMP 使用默认 Codexpress 绑定时随 Mac 选择切换。新请求使用所选实例的设备推理 Key，管理令牌只留在 Mac 管理端；无需把管理令牌填入 OMP。服务端设备表可单独撤销这台 Mac 的 OMP 设备。显式指定其他网关地址的独立 OMP 配置不随动，cmux 控制中心的独立模型连接也不因此改写。

随 0.8.38 提供的 OMP 扩展 0.1.14 会使用设备 Key 检查当前服务器是否提供 OMP 原生接口。新服务器使用 OMP 自己的模型目录、预算与绘图能力；旧服务器没有该接口时使用 Responses。拒绝授权、TLS 失败或重定向都不会触发换网关；上游账号及重置卡管理只在 Mac 管理端完成。

### 局部更新

替换磁盘上的 `Codexpress.app` 后，应用会在「设置 → 本机网关」提示已检测到的新版网关，不下载或自动切换。同系列的网关可点击「空闲后更新网关」：它会等待在途请求和后台写入结束，保留端口、Key、用量及原文缓存；新版恢复来源和原先在用的入口后才接收请求。切换期间新请求可能暂时无法连接，应用不会替客户端重发。新版启动失败会尝试恢复上一版。原生界面及不兼容的网关版本仍需重启应用。

## 直接官方登录

菜单栏面板、概览及「接入 → Codex」提供「直接官方登录」。点击后自动检查配置、等待 Codex 正常退出、切换到内置 OpenAI 提供商，并重新打开 Codex。复用 Codex 自己保存的 ChatGPT 登录；尚未登录时，在 Codex 原生界面完成授权。Codexpress 的来源池账号不会被复制进 Codex 的认证文件或钥匙串，两个客户端继续各自管理令牌。

此模式下 Codex 使用正常的系统网络和系统代理，不使用来源里填写的 Clash 端口。Chat、绘图和网页会话等原生功能由 Codex 版本及登录账号提供，本工具不实现这些功能。原生流量不经过本地网关，因此不参与优先级切换，也不计入逐源 Token 统计。需要返回时点击「使用来源池」，同样自动重启 Codex。

直接官方模式明确固定官方 Responses／ChatGPT 服务地址及 ChatGPT 登录方式，并启用系统代理。旧会话可能仍选择原供应商 ID，因此此模式会暂时把已声明的供应商 ID 指向官方地址并改用官方认证，完整原表保存在私有快照，返回号池时恢复。工具、历史及来源池设置保留，不改写会话数据库。启动时还会覆盖桌面端的服务地址环境变量、清空继承的 API Key／外部服务入口，并使用新建的本地 app-server，避免复用旧后台连接。系统代理环境不改动。

切换前自动备份认证文件，官方登录后即使 `auth.json` 被原生客户端重写，返回号池也会恢复号池模式下的认证文件；再次进入官方模式则恢复该模式上次保存的文件认证。Codexpress 来源池自身的 API 密钥由所选凭据存储管理，独立于 Codex 的认证。旧版本已经丢失且没有备份的 Key 无法自动重建，需从已有备份恢复或重新填写。

切换中的退出提示由 Codex 处理，30 秒内未退出则停止操作，不强制结束进程、不写入连接配置。受管字段已被外部修改，或当前配置档案覆盖连接／登录方式时，提示处理冲突后重试。管理员策略仍可能优先，旧会话的模型及运行时状态仍需在客户端核对。

## 配置与认证备份

点击「应用连接设置」、直接官方登录、切回来源池或恢复原连接时，先保存当时的 `config.toml`、`auth.json`、`auth.json.bak`、同目录的 `*.config.toml` 配置档案及本应用连接快照。设置中的「配置备份」可按时间选择「还原备份」；确认后正常退出 Codex、还原所选文件并重启。还原前会再备份当前状态，所以可以选择该备份撤回还原。

备份保存在应用数据目录的 `configuration-backups/`，每份独立保存，目录权限 0700、文件权限 0600；查询界面不返回认证内容。恢复前验证文件校验值，损坏、跨目录或符号链接的备份拒绝覆盖。完整备份还原会恢复配置文件到选定时刻，保留历史和其他非配置数据；「恢复原连接」仍采用受管字段合并。文件中不存在的认证也会按当时状态恢复。备份不包含其他应用的钥匙串内容，钥匙串登录需由 Codex 自身确认。备份失败会阻止本次配置写入。

## 供应商模型列表

来源编辑页默认选择「自动获取」。第三方通过 API 基址下的 `GET /models` 获取；基址以 `/responses` 结尾时使用同级 `/models`。支持 OpenAI 的 `data[].id`、Codex 的 `models[].slug` 及模型 ID 数组；其中 OpenAI API Platform 会自动排除 `whisper`、`tts`、`text-embedding`、`dall-e`、`gpt-image`、`realtime`、`audio` 等非对话模型。Google AI Studio 通过 `GET {base}/models` 分页获取支持 `generateContent` 的模型，并保留上下文窗口、最大输出与推理档位信息。官方账号登录后通过官方 Codex 模型目录获取。获取操作使用来源自身的网络策略，代理失败不会改用直连，不转给其他来源，也不计入生成用量。

官方目录会按客户端协议版本筛选模型。Codexpress 0.8.22 将目录查询及官方请求的兼容版本统一为 0.169.0，满足 6.2 系列要求的最低 0.166.0；旧版的 0.162.1 会得到不含 6.2 的目录，不代表账号无权限。更新后自动刷新或手动点击「刷新模型」即可，无需重新登录。OMP 通过 `/codexpress connect` 重新读取新增模型。

成功结果去重后保存在来源设置，并用于模型路由。启动后、来源保存及登录后自动刷新；打开来源页时检查更新，页面活跃期间每 5 分钟更新自动获取的模型列表，后台仍每小时检查一次，也可点击「刷新模型」。失败时保留上次列表并显示错误；未获取到列表时仍沿用空列表不限模型的既有规则。供应商不支持查询时可切换为「手动填写」，旧版本中非空的手动模型列表不会被自动覆盖。

刷新期间更换来源凭据后，旧请求返回的模型列表或错误不会覆盖新账号的数据。

未保存的新 API 来源也可获取模型，密钥仅暂时发送给本机网关，保存来源时才写入所选凭据存储。编辑已有来源的 API 地址后，自动获取需要重新填写密钥，避免在未保存时把原密钥发往新地址。官方账号修改代理后先保存，随后按新端口获取模型。旧的远程代理配置会保留，填写本地端口后才改用本地代理。

## 全局模型设置

「模型」顶部支持切换 **按模型** 与 **按供应商** 两种视图：

- **按模型**：集中展示来源声明的模型及已保存的自定义模型，每行带快速启用开关、状态筛选与批量启停，并显示来源、接入端、近期 Token、输入输出比，以及样本足够时的生成 TPS 和缓存命中率。悬停模型名称可查最大输入和压缩点；点击进入二级设置页，可选择允许的供应商及优先级顺序、可用接入端，以及上下文上限与压缩规则。
- **按供应商**：按来源池优先级排列全部来源，选择供应商后进入二级页面，按搜索或启用状态筛选并单个或批量启用／停用该供应商的模型，也可点击具体模型跳转至模型详情继续配置优先级或压缩规则。
- 新添加到 **Google AI Studio** 或 **OpenAI API Platform** 且自动获取的模型默认停用（不会自动开放给客户端；若同名模型已由其他来源提供，则保留原有来源不受影响），需在「模型」的任一视图按需勾选启用。

统计展示先从本机账本按请求开始时间取跨来源、跨接入端的最近 1,000 条已结束记录，不足 1,000 条时全部纳入。再按模型汇总输入与输出 Token、输入输出比、生成 TPS 和缓存命中率；列表按该窗口内的 Token 总量降序排列，同量按模型 ID 排序。模型在窗口内不足 10 条时仍显示 Token 和输入输出比，但不显示 TPS 与缓存命中率；没有记录显示 0 Token。达到 10 条后，TPS 与缓存命中沿用用量界面的计算口径；没有有效分母显示「—」，明确报告无命中显示 `0%`。

默认继承来源池顺序，并允许所有接入端。开启「自定义来源及顺序」后，选中的来源构成该模型的白名单，可上下移动排序；未选来源不参与该模型的请求。显式顺序优先于全局排序和负载均衡，允许来源上的会话粘性及手动抢占保留。普通自动请求仍遵守固定来源；显式抢占仍可临时覆盖固定模式，但不能绕过模型白名单。图片生成保留自己的指定来源，不跟随文本的固定模式。

来源必须声明支持该模型，来源模型列表为空时继续按不限模型处理。发现接口只补充可列出的模型名称，不将空声明收窄为发现结果。移除来源后，模型中保留的引用不会自动改成其他来源，可在详情中取消选用；显式选空来源代表停用，不等于恢复默认。

「可用接入端」按模型类型展示：文本模型可选择 Codex、OMP 和聊天客户端；`gpt-image-2` 可选择 OMP 和图片生成。设置同时控制该端的模型目录及实际请求。远端 SSH 使用对应客户端的同一规则；未开放的模型不会出现在该端模型列表，手动填写其 ID 也会收到 `model_not_enabled_for_client`，不提交上游。未选择任何适用接入端即全部停用。图片端仍只提供原有 `gpt-image-2` 能力，OMP 原生绘图也按实际图片模型的设置判断。

模型目录不会因暂时冷却、额度耗尽或并发满载而来回消失；上游目录未知且查询失败时仍明确报错，不冒充空清单。来源编辑页的原始发现清单不受客户端筛选影响。「恢复模型默认」撤销该模型的自定义策略和压缩覆盖，点击「保存模型设置」应用；未保存即返回列表不会应用编辑。直接官方登录的 Codex 流量绕过网关，不受这里的来源与接入端限制。


## 按模型自动压缩上下文

在「模型」列表点击模型，或「添加模型」，进入详情后开启「自定义输入与压缩」。压缩阈值和最大输入均为可选正整数，分别留空表示沿用模型／客户端默认；两项都留空时不保存压缩覆盖。同一模型在官方／API 来源及不同接入端共用规则，不再在 Codex 接入页单独编辑。默认最大输入取官方目录的 `max_context_window`，仅当该字段缺失时回退到 `context_window`；6.2 Sol 和 Astra 当前均为 872,000 Token，而不是其标准工作窗口 500,000／272,000。自定义最大输入不能超过这个官方上限；压缩阈值独立设置，仍不能超过实际最大输入的 90%。旧的超大覆盖保留在设置中供修改，有效预算按官方最大输入收敛，不阻断网关启动。

点击「保存模型设置」原子保存该模型的来源、接入端及压缩覆盖，并立即同步运行中的网关。只有 OMP 自动同步预算；保存设置或启动 Codexpress 均不会写入本地 Codex 配置。本地 Codex 在「接入 → Codex」点击「同步模型设置」手动更新，来源池与直接官方模式均保留原连接及认证，不自动重启 Codex；直接官方连接时不提示本地配置待同步。规则由 Codex 启动时加载，更新后需重新载入客户端，或下次启动后新建会话，VS Code 扩展需重载对应窗口。

远端 Codex 不自动写入：设置变化后，「接入」及已保存机器菜单显示待同步／待核对，需在「远端 SSH」重新预览并应用。预览后的规则或模型策略改变会使旧预览失效；只有实际应用成功才记录同步版本，提醒跨重启保留。OMP 自动取得新预算；其他聊天客户端需刷新模型目录，不读取预算元数据的软件仍需自行设置。清空规则或恢复原连接会按原流程还原模型目录及全局上下文设置。

规则通过 Codex 的 `model_catalog_json` 加载。优先基于原有自定义目录，其次所选目录的模型缓存，否则使用随应用附带的 Codex 基础元数据及经过验证的 6.2 能力补充；更新的官方目录优先于离线能力快照。刷新官方模型列表后，会保存其模型能力信息；重新应用规则时，旧目录缺少的新模型会从这些信息补入，保留推理档位、工具能力和模型指令。原有模型的自定义非预算元数据继续保留，原全局窗口和压缩阈值移入已知模型元数据，避免覆盖逐模型规则。生成的目录是静态快照，新增模型后需重新应用规则并重启 Codex；配置 profile、命令行参数或客户端设置的显式覆盖仍可能优先。模型 ID 的版本后缀匹配遵循 Codex 自身规则。

6.2 的 Codex 订阅能力与公开 API 上限不同：当前官方目录给出 Sol 标准工作窗口 500,000、Astra 标准工作窗口 272,000，最大输入均为 872,000；标准工作窗口不作为自定义最大输入的上限，也不直接等同于自动压缩点。OMP 使用最大输入预算与独立压缩规则，不直接套用公开 API 的 1,050,000 总上下文。公开 API 的 `prompt_cache_options`、显式缓存断点及缓存写入价格，不代表 Codex OAuth 后端的支持或订阅实扣政策；网关不会为 6.2 自动注入这些字段或改写现有缓存键。

生成目录同时兼容较旧的 Codex：对缺少 `base_instructions` 的条目，从现有 `model_messages.instructions_template` 补齐旧版必需字段，已有值及新版元数据保留。本机和远端 Codex 均需在接入页手动更新配置并重新载入客户端。

压缩阈值不能超过上下文窗口的 90%；窗口值应与上游真实能力一致。压缩由 Codex 发起，正常路径继续透传，网关不自行生成摘要；下述最终兜底仅在无法续接时按明确设置移除请求副本中的加密状态。当前自定义 provider 的 CLI 通常通过 Responses 生成摘要；客户端使用 `/responses/compact` 时也支持转发，包括官方源的指定代理。官方真实账号压缩仍需实测。

以下 5 秒预算同步指连接 Mac 内置 `/omp/v1` 的方式（含通过 SSH 配置的客户端）；独立服务器 `/v1` 不提供该预算探针，扩展不会为此持续访问服务器。

Codexpress **0.8.14** 与扩展 **0.1.7** 起支持本机及远端 OMP 每 5 秒轻量检查预算版本，空闲时也会更新。现在版本同时跟踪模型基本能力与压缩规则：目录窗口、推理档位或价格变化后也会重新读取，内容相同不反复刷新，不查询余额或调用模型生成。版本变化后更新当前模型窗口及固定 `fN` 压缩点，不重选模型、不清理历史或原生会话；输入和新一轮开始前也会检查。OMP 手动设置仍优先，但窗口不得突破网关公布的上限；没有所有权记录的旧阈值不会被自动接管。网关离线时保留最后成功预算，恢复后继续同步。新增模型也可通过 `/codexpress connect` 刷新。

Codexpress **0.8.17** 与扩展 **0.1.8** 补齐旧版一键配置的归属迁移：本机根会话会按同一 profile 的旧快照，接管仍未改动的 Codexpress 压缩点，并移除旧版受管窗口覆盖，让后续预算真正跟随网关。手改或删除的值、其他供应商、输出上限和压缩策略链保留；没有可验证归属的字段不猜测接管。旧归属交接后不再重复认领，之后手设回旧值也会保留。升级后先重启 Codexpress，再重新加载 OMP 扩展或重启 OMP 一次，无需重新登录或改动 Codex 配置；远端连接继续原有预算同步，不执行本机快照迁移。

「模型 → 模型能力 → 导入 JSON」可以单独修正默认上下文上限和压缩点，例如 `{"models":[{"slug":"gpt-6.2-sol","max_context_window":872000,"auto_compact_token_limit":null}]}`。导入立即更新网关目录和 OMP 预算。每次导入替换整份本地能力，未列出的模型仍使用官方缓存或内置数据；`null` 表示客户端默认。单模型规则继续优先，但受窗口上限和 90% 压缩边界限制。无效文件保留上一次结果，「恢复默认」只清除导入的能力，不删自定义规则。导入不修改价格，也不会写入本地或远端 Codex 的配置。

## 官方额度与重置卡

打开来源页或展开菜单栏面板时，会刷新其中已启用来源的账户信息。官方账号的正常后台查询间隔可在「设置 → 官方额度」独立设置，单位为正整数分钟，默认 30 分钟；保存后立即生效。某个官方账号额度查询失败后，该账号改为每 5 秒查询一次额度，成功后恢复正常间隔。并发查询仍合并，不会每 5 秒查重置卡，也不改变 API 来源的余额刷新频率。正常情况下，打开界面时会复用 15 秒内的额度；手动刷新可立即查询额度和库存。查询失败时保留上次数据并标注「更新失败」。没有短周期的账号不显示短周期；窗口存在但数值缺失时显示「未知」。

官方七天窗口显示 `ref`，表示本次刷新周期的剩余时间百分比：`(下一次重置时间 − 当前时间) / 七天 × 100%`，限制在 0–100%，不按自然周计算。周期开始为 100%，重置时为 0%，可与实际剩余额度直接对照。没有短周期额度时显示在周额度旁；有短周期时在周额度下方以小字显示。原生界面和 cmux 按本地时钟倒计，不追加上游查询；缺少有效重置时间及参考值时不显示，到期后保持 0% 等待新周期数据，不自行推算下一轮。

`ref` 与实际剩余额度比较：`ref − 实际剩余` 达到 5 个百分点显示黄色，达到 10 个百分点显示红色，否则使用次要文字色；实际剩余未知时不告警。只有 `ref` 改色，周额度自身的原有配色、使用量、计费和路由逻辑不变。OMP 的标准 `/usage` 概览在周额度标签中显示参考值；完整的分层布局和独立配色在 `/codexpress status` 中查看，不修改原版 OMP 核心。

重置卡随账户信息刷新按需查询，5 分钟内复用已有结果，不另设后台轮询。手动「刷新额度」及使用重置卡前会一起更新额度和卡片。

概览和来源池在官方额度旁显示重置卡数，可直接查看卡片。主额度耗尽且有可用卡时，显示「立即重置」。菜单栏面板有可用卡时显示图标和数量，没有时隐藏；主额度为 0 时额外显示「重置」按钮。点击会刷新库存并选中最早到期的可用卡，确认账号／工作区、卡片及到期时间后才消耗。也可返回列表手动选卡。

在「来源池」展开某个官方账号的详情，可为该账号开启「自动使用重置卡」，默认关闭。旧版总开关不会授权任何账号；如需使用，请逐个开启。只有主要周额度耗尽才会选择最早到期的可用卡片，无需逐次确认；短周期、附加模型限额和普通限流不消耗卡片。手动使用或经管理 API 使用重置卡仍需弹窗确认。关闭开关不能撤回已提交的用卡操作。

官方来源首次明确拒绝请求并报告额度耗尽时，网关暂缓向上游发送新请求；已经发送的请求不会被打断，同一轮的重复拒绝也不会再启动一次重置。有短周期、或无法确认只有周额度时，先查询官方额度；已确认只有周额度时，直接检查卡片。用卡后立即查额度，若仍未恢复，间隔 500 毫秒继续查询。单账号的恢复流程最多等待 15 秒；没有可用卡、未开启或没有及时确认恢复时，按现有优先级与模型规则尝试其他来源。

同一次耗尽不会重复提交用卡，即使重启也不会重放。用卡结果不明时只查询，不换卡重试；确认恢复后再次耗尽，或新周期再次耗尽，才可能用下一张卡。对话还未开始输出时，网关可在确认恢复后尝试续跑，或切换至兼容来源，不转发中间的上游额度错误。已输出的内容不会重放。所有匹配来源都确认耗尽才报告额度耗尽；暂时无法恢复或无匹配来源时返回可重试的网关错误。

可添加多个不同的官方账号，额度、卡片与重置操作各自独立。同一账号不能重复添加为多个官方来源；登录时自动检查，已存在时提示使用对应来源。重复点击不重复提交；网络结果不明时保留「待核实」，只重新查询卡片和额度，不自动重放消费请求。重置成功后刷新额度，确认恢复后该账号重新参与分配。累计 Token 统计保留。

额度刷新只占用当前来源的刷新状态，不锁住其他来源操作；不足 1% 的可用额度显示为「<1%」。刷新令牌若返回不同账号，会保留原登录并要求重新登录，不自动换成另一账号。

## 自定义来源余额

编辑自定义来源时可开启「余额不足时通知」并填写预警余额，单位跟随供应商返回的币种。余额达到或低于阈值时发送系统提醒，例如「Clauder 余额不足，当前余额 US$ 9.50」。低余额期间只提醒一次，重启应用也不会重复；充值恢复到阈值以上后，再次不足时可重新提醒。查询失败、过期数据或无法获取余额不会触发预警。关闭预警不影响余额查询，也不会停用来源。

来源卡片与菜单栏面板展示剩余可用余额；刷新期间保留旧金额，并显示加载符号。首次查询中显示「查询中…」，接口不支持或全部查询失败时显示「无法获取」。更新失败保留旧金额，并提示错误和上次更新时间。停用来源不后台查询，仍可在来源卡片手动「刷新余额」。重命名、排序和启停来源不会清空有效余额。

USD 余额查询成功后，以该次上游结果为基底，随后按本机已结束请求的消耗动态扣减：已有实际扣费时采用实际值，尚未核对时采用参考费用；后续账单核对只替换原暂估值，不重复扣款。新的上游余额查询始终优先，成功后重新建立基底，不再叠加此前请求或其迟到的账单修正。没有有效基底、币种不是 USD 或费用未知时，不伪造动态金额；其他客户端消耗和充值以之后的上游余额查询为准。

设置预警余额后，余额高于预警值 5 倍显示绿色，高于 1 倍且不超过 5 倍显示黄色，达到或低于预警值显示红色；未设置预警值时使用中性色。官方剩余额度高于 30% 显示绿色，高于 10% 且不超过 30% 显示黄色，10% 及以下显示红色。颜色不影响来源优先级或自动切换规则。

来源正在处理请求时，状态绿点闪动；网关有进行中的请求时，菜单栏图标右下角显示绿点。活动状态约每秒更新，闲置对话不持续点亮；开启系统「减少动态效果」后，来源绿点保持常亮。

打开相关界面时按需刷新，另外每 30 分钟后台更新一次。普通余额查询成功后 15 秒内复用结果；自动查询连续失败后依次等待 1、2、4、8、15 分钟，之后维持 15 分钟冷却。手动刷新和管理 API 的主动余额刷新绕过成功缓存及失败冷却，同来源并发请求仍合并；成功后清零失败次数。优先复用已识别的余额协议，Claude Code Hub 临时登录会话只保存在内存中，过期或认证失效后重新获取。退避只限制自动余额查询，不阻止正常对话。

支持 Claude Code Hub、New API／One API、Sub2API 钱包或密钥总额度、OpenAI 兼容余额接口，以及 DeepSeek、Moonshot、SiliconFlow、OpenRouter 的常见钱包格式。接口返回总额度与累计已用时，转换为剩余额度；不把每日／每周限额、无限额度哨兵或缺失数据当作余额。优先显示账户总余额，只能获取密钥总额度时显示该密钥的可用余额，悬停可查看范围。New API 标准 quota 单位按 500,000 quota = 1 USD 换算；不同币种不做无依据的合并。

仅访问来源自身的站点与路径，沿用该来源的直连／系统代理／指定代理规则，不跟随重定向、不向第三方探测服务发送密钥。查询不发起模型生成，也不改变来源优先级或可用状态。

## 官方账号图片生成

在「来源池」登录官方账号后，打开「接入 → 图片生成」。生图使用独立的本机端口（默认 `17866`）与独立 Key，沿用官方来源的网络策略（系统代理或指定代理），使用该账号的套餐权限。可按官方来源优先级选择账号，也可指定一个账号；此选择独立于文字对话的固定来源设置。聊天短周期或周额度为 0 时仍可尝试生图，实际限额以官方生图接口返回为准。停用、需要登录、网络冷却中的账号及并发已满的来源不会参与分配。

点击「复制接入提示词」，将内容发给本机 Codex 或其他 Agent。Skill 和 Python 3 调用脚本随 `.app` 分发，无需另外安装到 Codex 目录。提示词只包含应用内 Skill 路径及私有配置路径，不包含密钥；配置保存在 `~/.codexpress/image-client.json`，文件权限为 `0600`。在本页更改端口或重新生成 Key 后，已导出的配置会同步更新。将应用交给其他用户时，由对方登录自己的账号并复制自己的接入提示词。

其他支持自定义 Images API 地址的 Skill／客户端，可填写本页的 API 基址和独立 Key。支持 `/v1/models`、`/v1/images/generations` 和 `/v1/images/edits`，模型为 `gpt-image-2`，返回 PNG 的 `b64_json`。编辑支持 JSON 内嵌图片及 OpenAI SDK 常用的 multipart 图片上传，最多 5 张 PNG／JPEG／WebP，每张 10 MB、合计 32 MB；不支持远程图片 URL、mask、流式输出及 JPEG／WebP 输出。尺寸与质量以官方账号实际支持为准。

脚本的 `check` 命令只检查接入与模型列表，不生成图片。生图超时、连接中断或服务端错误时不自动重放，结果未知的请求可能已消耗额度；使用其他 SDK 时也应关闭自动重试。明确收到 429 拒绝时，自动选择模式可尝试下一个可用官方账号。请求会出现在用量记录中，未返回图片 Token 计数时不按图片 base64 大小估算文字 Token 或输出 TPS。

## 来源优先级与对话接续

「来源池 → 分配策略 → 上游重试」可设置单个来源的尝试次数和失败后的等待时间，默认 **3 次、3 秒**，次数包含首次请求；设为 1 次可关闭额外重试。连接建立明确失败、临时限流（HTTP 429）及 HTTP 500／502／503 等暂时服务错误会先在当前来源重试，预算用完后再按路由规则切换。等待从上一次失败后开始，期间保留活跃对话名额。Codex、本机／SSH、压缩端点和聊天客户端共用此设置。

已明确的额度、认证或参数拒绝不会反复重试；HTTP 408／504、提交结果不明的传输中断及已经开始输出的流保持原错误。每条客户端请求的预算会跨上下文重建和配置重规划保留，避免重复获得重试次数。固定来源模式重试后仍只使用所选来源。

自动切换默认关闭「负载均衡」。每个新对话从可用来源中优先级最高的兼容来源开始，收到上游明确错误或拒绝、确认连接尚未提交，或达到活跃对话上限时，再按顺序尝试下一个。其他对话触发的临时冷却、非零的低余量不会让新对话提前跳过首选来源。官方短周期或周额度任一归零，或上游明确返回额度耗尽时，此账号暂不参与分配；新对话、已有粘性和手动插入均不能绕过。确认余量恢复后重新参与，经过重置时间但尚未查到恢复数据时继续跳过。停用、缺少凭据或不支持所选模型的来源不参与分配。

「来源池 → 分配策略 → 对话接续 → 粘性保持时间」默认为 **5 分钟**。成功接续会刷新计时，失败探测不延长粘性；闲置到期后，下一次请求重新从最高优先级开始。正在返回的回复不会因计时到期而迁移。可调整保持时间，也可选择不自动回切。网关重启后保留成功来源和活动时间，最多保存 100000 项；到期不删除对话绑定或原文缓存。

开启「来源池 → 分配策略 → 负载均衡」后，新对话优先使用近期活跃对话较少的可用来源，数量相同时按优先级选择；已有对话保持来源，不按上述计时回切。此模式保留健康状态、额度与官方余量保护检查。固定来源模式不自动跨源。

在「来源池」或菜单栏面板点击「立即恢复」，可清除临时冷却或代理故障，不改变额度与登录状态。「立即抢占」持续让后续对话请求优先尝试指定来源，直到达到该来源的活跃对话上限，或其他来源已经没有活跃对话；未设并发上限时，以清空其他来源为目标。接续请求成功后继续抢占，不会在第一次成功后结束。临时故障按「上游重试」的次数和等待时间先重试当前来源，全部失败后才停止抢占并回退；额度耗尽、认证失效等明确的不可恢复错误可直接停止。尚未输出的明确流式临时错误也使用同一重试预算；已开始输出或提交结果不明确的请求保持原有保护，不重复发送。

抢占可越过临时冷却、优先级、固定选择和低余量保护，仍遵守活跃对话上限与官方额度耗尽检查。点击「停止抢占」可结束后续抢占，已提交的请求继续执行；再次指定来源会替换当前操作。没有其他活跃对话时，仍先尝试一次选定来源。模型列表、压缩请求不参与抢占；模型不支持时按正常路由处理，来源停用或身份变化会结束操作。切换发生在后续请求到来时，不中断正在输出的回复；不改变来源排序与路由设置，应用退出后不保留。菜单栏的按钮位于来源名称与状态之间，恢复按钮只在临时故障时显示。

Codex 使用官方连接时，OMP 等客户端仍可继续使用网关来源池；来源抢占、停止抢占、恢复与分配策略独立可用，不受 Codex 连接模式影响。

手动抢占先原样提交已有对话 ID、加密块和轮次状态，让目标上游判断能否续接。明确拒绝后，若已开启上下文兜底且能够重建，会先在目标来源修复后再试一次；仍然失败才回到正常路由。已开始输出、未知的流错误及提交结果不明的超时不重放。目标确认接受旧状态后，兼容结果只对当前对话和模型保存，不改变其他对话共用状态的来源归属。

编辑任一官方或第三方来源，可开启「限制活跃对话数」，设置对话上限和空闲释放时间。默认不限制；开启时预填 3 个、15 秒，可按供应商实际承载能力调整。正在请求或接收回复的对话一直占用名额，不会因持续时间较长而过期；最后一个请求结束后保留设定的短窗口，同一线程和模型的后续请求复用名额。不同模型分别计数，无线程标识的请求分别占用名额。

名额已满时，自动模式会为其他对话选择下一个可用来源；固定来源模式不会绕过限制。来源池与分配策略显示当前占用与上限。这一短窗口只用于限制活跃对话，与来源粘性、缓存闲置回切及官方余量保护的时间独立。

负载均衡模式显示「官方余量保护」，默认阈值为 **10%**，可调整。短周期或周额度任一已知剩余不高于阈值，且该官方账号已有活跃对话时，为其保留余量；没有活跃对话时允许接收一个新对话。保护窗口为最近 30 分钟的成功请求及仍在接收的回复，同一账号的多个来源共用保护。此模式下主额度归零会跳过官方来源，查询失败保留此前已知余量，明确恢复后解除。

停用的来源不再参与新的分配，已有绑定也不能绕过停用开关。请求若仍在等待 OAuth 或准备上下文，期间变更开关、排序或路由设置，会在提交前放弃旧选择并重新规划。已经开始向上游提交的请求及正在返回的流保持运行。此规则用于来源池模式；「直接官方登录」由 Codex 原生连接，不受池内排序控制。

来源粘性按线程和模型区分。活动记录保存在本应用私有的 `affinity.sqlite` 中，只含摘要、来源身份与活动时间，不读取 Codex 历史。请求的 `prompt_cache_key`、正文与上游路由标记原样保留；来源身份变化使旧偏好失效。

## 旧对话接续与最终兜底

本地找不到对话 ID 的映射，不代表上游的 ID 已失效。默认优先级模式和手动插入会先保留原 ID、加密块及轮次状态，交给目标上游验证；不会仅因本地绑定不同就提前删除。新对话或粘性到期时从最高优先级开始，粘性期内先尝试当前来源。收到明确拒绝后，在同一次客户端请求内尝试后续来源；全部无法原样接续时，才进入上下文重建。未知的流错误、已产生输出或提交结果不明确时不重放，HTTP 408／504 也保留原错误。

负载均衡和固定来源模式仍保留原来源约束。仅本地缺少 ID 映射、且没有加密状态约束时，可按来源线索逐一探测，最多 5 个来源；明确拒绝后才尝试下一个。

曾转接过的对话在当前来源故障后仍可再次交接；完成上下文重建后，旧转接目标不再限制本次路由。连接建立阶段明确失败、确认请求尚未提交时，也会尝试在本次请求内重建并交给其他可用来源。原文缓存缺链仍会停止恢复，避免发送截断历史。

负载均衡或固定来源模式下，没有可用来源是由临时连接冷却、代理故障或活跃名额占满造成时，网关会在单次请求内等待恢复，最多 20 秒；超过期限返回 HTTP 503 和 `Retry-After`。等待不会绕过停用、认证失效、已知额度归零、模型或原来源限制。默认优先级模式直接依次探测候选来源，不因其他对话触发的全局冷却在本地拒绝。

「接入 → Codex」的连接预览提供「已有对话的原来源」。确认原供应商与来源池中的 API 使用同一账号和密钥后，旧对话可以通过专属本地凭据回到原来源，保持正文及加密上下文。地址、密钥或配置目录变化后需重新确认；未确认的旧供应商连接保持原样。

「来源池 → 分配策略 → 对话接续」默认启用最终兜底。原来源无法续接、未知状态被本地拒绝，或上游明确拒绝且另有可用来源时，网关最多尝试一次重建：移除本次请求的加密推理／压缩块及旧响应／会话／轮次状态引用，保留可见历史和工具结果，再按正常规则分配。隐藏推理或压缩摘要可能缺失，因此它是尽力恢复，不是无损迁移。已开始的流及提交结果不明的请求不会自动重放，固定来源模式仍不跨源。

触发时发送系统通知；官方来源变为额度耗尽时也通知一次，恢复后再次耗尽可再通知。首次需在 macOS 允许 Codexpress 通知；拒绝权限时，应用内显示同批提示。只有上游确认接受后才保存重建与兼容状态；失败探测不会替换已确认来源。粘性到期后仍先交给上游验证，接受时无需再次重建。关闭最终兜底或原文缓存缺链时，不会删除加密块后发送不完整历史；无法原样续接则返回错误。本地对话不会被删除或改写。

子代理继承的历史也可能含上游专属状态：默认优先级模式会先交给目标上游验证，明确无法接续后才重建。仅准备过但未实际提交的恢复，以及没有移除旧状态的来源切换，不会触发恢复提示。安全诊断中的 `routing_attempt` 记录来源索引和选择原因，不包含对话正文或状态引用值。

## 官方来源的网络状态

来源池中的官方账号使用该来源指定的本地代理端口；「直接官方登录」使用 Codex 自身的网络路径。TUN 接管的是网络路由，不会自动替代来源里填写的 HTTP 代理端口。因此，原生登录可用并不能证明指定端口的代理握手和上游连接也可用。

网关按来源及网络策略复用 HTTP 连接，减少重复的代理隧道与 TLS 握手。修改来源地址或代理后使用独立连接池；官方来源不会因代理失败改为直连。空闲连接最多保留 60 秒，最多缓存 256 组来源连接池。

同一请求对同一来源至少收到 **3 次明确的暂时性上游 HTTP 错误**，且重试预算已用完，才会记录临时冷却。一般错误冷却 15 秒，429 按上游 `Retry-After` 或默认限流时间处理。设置仅尝试 1–2 次时仍可切源，但不会因此全局冷却；连接失败、认证查询网络错误、单次参数错误或流中断也不会单独触发冷却。确认的认证失效与额度耗尽使用独立状态。

默认优先级模式仍会在新对话中按排序重新尝试，负载均衡和固定来源模式会遵守已有冷却，也可点击「立即恢复」清除临时故障。本次请求的交接不依赖全局冷却，因此不会为了切源而暂停其他对话使用原来源。错误提示区分连接建立超时、连接建立失败、请求超时和数据传输中断。连接建立阶段仍可能涉及 DNS、代理隧道和 TLS，单条提示不能确认是哪一个环节。

官方额度查询成功后，会清除查询开始时已有的临时代理故障。查询期间新发生的故障不会被旧查询结果覆盖；认证失效、HTTP 限流和额度限制保持独立。额度查询失败则保留旧快照和故障信息。

## 实时用量与费用统计

「用量」默认显示近 30 天，可选近 1 小时、近 5 小时、1 天、7 天、90 天、365 天或不超过 366 天的自定义日期，并按来源与模型筛选。小时档位以当前时刻向前滚动，汇总、性能、Token 趋势和连接日志使用同一精确窗口，趋势按 5 分钟聚合；日期档位仍按 Mac 的本地日界线划分。总览展示参考费用、总 Token、请求与成功率；平滑的 Token 曲线可悬停查看数值，活跃面板可单独切换月／年：月视图保留铺满宽度的网格，年视图展示完整一年的密集方格，按每天的输入加输出 Token 深浅着色；没有数据的日期填灰色。月视图显示日期和 Token，年视图只显示色块，悬停时在图下立即显示日期、Token、请求数和参考费用；点击日期色块可固定详情，再次点击或按取消按钮解除。两种视图从所选结束日期分别回看 30／365 天，并沿用来源和模型筛选。用量占比可按供应商或模型分类：供应商按参考费用排序和分配扇区，模型按 Token 量排序和分配扇区，中心显示对应总量。前三项列在图右侧，同时显示费用与 Token，其余合并为「其他」；未知模型始终并入「其他」，不受分类数量影响。悬停扇区可高亮对应分类。概览不单列未知或未计价模型，具体记录可在连接日志中查看。统计覆盖所选时间范围内的全部记录。

供应商统计先去掉名称首尾空白，再将同名来源合并，统一累计请求、Token、费用及性能样本；例如 `LeoS` 与 `LeoS ` 视为同一供应商。不同模型仍分别统计，没有名称或仅含空白的来源按各自 ID 隔离。此规则仅用于统计显示，不改写历史名称、来源配置、余额或账单身份；请求明细和按来源筛选仍使用各自来源 ID。

面板依次展示汇总、用量占比与性能、每日活跃、Token 趋势。用量占比与性能指标在同一卡片中并排展示，饼图与分类明细在左侧区域垂直居中。性能区默认显示汇总，可单独选择来源；包含平均输出 TPS、首 Token 和请求耗时的 P50／P95、缓存命中率、平均费用与缓存节省。页面在前台显示时自动更新；切换页面、关闭或最小化窗口、切到其他应用后暂停统计和日志列表查询，重新打开时按最新日志补齐。后台继续记录请求用量，不持续计算图表。

概览、用量汇总、性能来源、供应商／模型分组、活跃日历明细、Token 趋势、模型列表及请求详情均显示输入输出比，网页同步提供总览、来源 × 模型和每日／每 5 分钟分桶的比值。按各自统计范围的输入 Token 总量除以输出 Token 总量计算，显示为 `12.3 : 1`，不是先计算每次请求的比值再平均。输入包含缓存读取，缓存和推理均不重复累加；含估算计数时标记 `≈`，输出为零或计数不可用时显示 `—`。比值沿用当前筛选和已有汇总缓存，不新增请求明细扫描。

自 **0.8.19** 起，用量统计在本次应用运行期间保留最近使用的 8 组内存快照，按时间范围、来源、模型和入口分别缓存；近 1／5 小时按各自滚动档位复用，不与日历日期或其他筛选混用。再次打开立即显示对应缓存，5 秒内复用结果；缓存过期时先显示上次统计和更新时间，再后台刷新，失败不清空已有数据。同一查询的并发读取合并，离开页面不会丢掉已发起查询的成功结果。时间、来源、模型、活跃月／年和性能来源选择在页面切换后保留；跨日使用新的日期范围，滚动窗口保留缓存实际对应的时间边界。首次查询、被淘汰的筛选或重启应用后仍需加载一次。页面停留时，统计及性能继续按原有 1.5 秒节奏刷新，独立活跃卡每 5 秒刷新；离开页面后不新增轮询，不因缓存而访问上游余额或发起生成请求。

自 **0.8.20** 起，网关统计也保留最近使用的 8 组缓存。有新增请求时，优先选择同筛选、同时间范围的最新缓存，按落库序号补算新增部分；较早开始、较晚完成的请求同样会计入，不会与进行中数据重复累计。没有同范围缓存时，会尝试复用时间桶对齐、被新范围完整包含的最新缓存，只补充新增记录和扩展区间。自 **0.8.21** 起，分位数使用精确耗时频率表，每组最多保存 8192 种不同值；超过后改用 SQL 精确计算，不近似、不平均已有 P50／P95，也不随请求数无限保存样本。历史费用修正、删除、影响既有记录的诊断更新、外部数据库写入会重新计算；筛选不同或时间桶不兼容时也重新计算，包括近 1／5 小时滚动边界移动后无法对齐的情况。本机、网页和管理 API 共用这层统计缓存，不保存额外正文。

切换「连接日志」查看请求列表。支持日期、上游来源、模型、入口、成功与否和元数据关键词筛选；在统计和日志之间切换会保留本次筛选。每页 50 条，可继续加载较早记录；连接中、流式接收中的请求优先显示并实时更新。每一次上游尝试独立记录，重试与切源可在「相关尝试」中切换查看。

入口单独记录为 Codex、Codex（SSH）、OMP、聊天客户端或图片生成，可在本机及网页日志中查看、筛选。OMP 扩展发起的绘图仍记为 OMP；独立图片接口记为图片生成。入口在请求创建时确定，随用量记录保存；旧记录沿用已有诊断中的入口，未记录的保持「未知入口」，不按模型或上游供应商推测。

请求详情包含状态、HTTP 状态、Token 与计价、耗时及输出速度。失败请求额外保留上游错误反馈、错误代码、响应头和调整过的参数名称，可分块读取或复制。成功回复正文与传入请求正文不保存在这些日志中。旧版本未保存的错误反馈会明确提示缺失，不能从计数还原。

错误反馈保存前会隐藏已知来源凭据、认证字段和常见令牌，存入应用私有用量数据库；响应头只保存白名单字段，URL 不保留查询参数。单次错误反馈最多保留 8 MiB，压缩正文总容量为 128 MiB，保留 30 天，超限先清理最早的正文，状态、计数和性能记录继续保留。超限、传输不完整或已清理都会在详情中标明。错误响应中的业务文字仍可能含敏感内容，分享前可先检查复制的反馈。

每条记录展示输入、输出、缓存命中、缓存写入和推理 Token。上游计数优先；缺失的输入或输出按字符估算，并以 `≈` 和「字符估算」标明，后续获得计数时替换。中文等约 1 字符/Token，其他文字约 4 字符/Token；图片、音频、文件及加密内容不纳入字符估算，无法观察的输出保持未知。缓存和推理数值只使用上游报告。

输出 TPS 从网关收到首个流式输出 Token 开始，到收到生成结束事件为止；不计首 Token 等待、结束后的传输尾部和输入 Token。模型及来源汇总按成功样本的输出 Token 总量除以对应时长之和。旧记录优先使用可信的生成计时，缺少时沿用请求总耗时。新记录缺少有效计时或上游确切输出量时不计入，例如一次性返回的 JSON。详情单独保留首 Token 延迟和请求总耗时。上游缓存后集中发送，仍可能使测得的输出速度高于模型真实生成速度。

流式响应的详细计数通常在响应结束时到达，接收期间可能先显示估算值。此前未采集到且未保存正文的详细计数无法补算。

请求结果以已观察到的结束事件为准：收到 `response.completed` 后，客户端关闭流不会把“完成”改为“已中断”；明确的上游失败保留“失败”。没有完整结束事件便提前断开的响应仍为“已中断”。Token 计数是否完整单独标记，缺少 usage 不代表请求中断。旧版本留下的误标记录不会仅凭连接状态自动改判。

## 参考费用与价格表

费用优先采用上游明确提供的单次 USD 扣费。已识别为 Claude Code Hub 的来源还会通过其只读自助账单核对历史记录：按来源、模型、输入／输出和缓存 Token、时间及耗时交叉匹配，并处理缓存计数口径差异。仅在本地记录与账单双方都唯一时替换参考价，详情显示「上游实际扣费」及账单记录编号；正常的零扣费也会保留。存在歧义、计数不完整、账单不可用或单位不明时继续使用参考价，不根据余额变化猜算单次费用。

支持账单核对的来源累计 50 次已结束的上游请求后自动核对；不足 50 次时，在该来源没有进行中请求、停止活跃满 5 分钟后核对。无需打开用量页面，读取状态或统计不会触发上游核对；没有新请求不会反复核对。手动核对不受批次限制。每轮使用分页读取，已完成的历史扫描会留下核对标记，后续只检查新记录及近期尚未结算的请求；中途失败不会提交不完整的匹配或推进核对标记。只保存金额、匹配编号和必要的核对标记，不保存账单原始响应、认证 Cookie 或成功回复正文。

没有新的核对任务时保留上一次核对的进度和结果，不因空闲检查清零。查询途中变更来源身份或代理时，旧任务不能认领新来源的本地账本。

新请求在账单核对完成前显示「暂估」，取得实际金额后改为「扣费」。打开的请求详情会在窗口活跃时刷新进行中的记录和近期成功请求的费用，无需关闭后重开；刷新只读取状态与计价，不重复解压错误正文。上游账单延迟、匹配不唯一或请求未完整结束时，记录可能持续显示估算。

用量页的「API 价格表」列出内置的 OpenAI 官方价格、核对日期及原始链接。当前版本更新于 **2026-10-29**，已收录 GPT‑6.1 Terra：输入 $1、缓存读取 $0.05、输出 $5，单位均为 USD／百万 Token。上游未提供可用扣费时，官方账号和第三方 API 都使用这张表折算参考费用，便于比较使用量；金额不代表 ChatGPT 订阅扣费或第三方实际账单，不包含工具调用、图像、音频、税费与地区附加费用。

每次请求分别计算非缓存输入、缓存读取、缓存写入和输出费用。缓存读取及写入是输入 Token 的子集，计价时从非缓存输入中扣除；推理 Token 属于输出，不重复加价。响应中的实际模型及服务等级优先于请求声明，未收录模型、未知计费模式与缺失计数单独标明，不当作免费请求。缺少缓存计数时按未命中估算；缺少输出或缓存写入价格时只计算已知部分。Fast／Priority、Ultrafast、Flex／Batch 仅在已收录对应价格时计算。

[官方 API 价格表](https://developers.openai.com/api/docs/pricing)仍区分部分模型的长上下文计价。例如 GPT‑6.1 Sol 输入超过 **272,000 Token** 后，整条请求的输入／缓存按 2 倍、输出按 1.5 倍折算。部分模型官方按整段会话判断长上下文，本应用按每次请求的输入量近似，详情会标明这一限制。

[官方订阅计价说明](https://learn.chatgpt.com/docs/pricing)明确从订阅额度消耗的 GPT‑6.1 Sol 不收长上下文费用，因此官方账号的该模型按基础单价参考折算。第三方来源可在「编辑来源 → 费用估算」开启「订阅来源」，开启后该来源所有模型均免长上下文加价，其他服务等级倍率仍按已知价格计算。此开关不改变供应商的真实收费。新版请求使用发生时的计价快照；旧版本记录按来源当前设置补算。

新版每条请求保存价格版本、计价模型、来源计价方式、有效单价及费用分项，修改来源或升级价格表不会重算这些快照。旧版本记录使用当前价格表补算，并标记「历史参考价补算」；来源仍存在时，按它当前的类型及「订阅来源」开关计价，之后修改开关也会重新计算这些旧记录。已移除来源保留上次补算结果；无法匹配来源时按 API 参考价计算并标明来源类型未知。历史未采集的详细 Token 不能补齐。总计与均次费用只包含可计价部分，旁边展示已计价覆盖数、未收录、部分计价及无有效计数的数量。

更新价格表后，此前因未收录模型或计费模式而无法计价的请求会重新尝试计算，保留请求当时记录的来源计价方式；已经计价的请求保持原快照。

## 本地原文缓存

Codex、本机与 SSH 共用入口、聊天客户端入口不设固定的请求正文大小上限，实际可接受大小由上游决定。上游明确返回 413 时按路由规则尝试后续来源，没有其他来源时保留上游错误。大请求仍需要本机有足够内存解析和转发；上传中断会返回读取错误。诊断日志只记录正文的字节数、入口与失败类别，不记录正文或认证内容。

「设置 → 本地原文缓存」默认启用，容量为 **5 GB**，可调整为 0.064–1000 GB。保存开关即时生效，容量可按回车或点击「应用容量」提交，两者互不提交草稿。它只保存启用后经过网关、成功完成且已完整观察的 Responses 输入和回复，包含工具调用、工具结果以及该请求的指令和工具定义。不会读取 Codex 历史库或补齐启用前的内容。直接官方登录的流量不经过网关，不会采集。上游的 `store: false` 控制上游存储，本地是否缓存由这里的开关决定。

内容按 JSON 项切分为最多 64 KiB 的增量块，去重后压缩保存。重复历史通过共享块和顺序引用复用；再次使用或读取某个块时更新该块的最近使用时间。容量不足时按块淘汰最久未使用的内容，不按整条对话删除，也没有固定的 30 天过期规则。容量上限包含缓存数据库中的压缩内容与索引，SQLite 写入和清理时可能短暂使用额外的事务日志空间。

需要放弃旧 `previous_response_id` 并重建请求时，网关可从完整缓存链补齐此前输入和输出，再附加本轮新增内容。认证范围和线程之间隔离；工具调用与结果保持原有顺序和配对。该操作仍遵守来源路由和最终兜底设置，不会重放已经开始输出或提交结果不明确的请求。

缓存和历史重建不设单条上下文的 32 MiB 上限，缓存磁盘占用仍遵守设置的总容量。若任何必需块已经淘汰、损坏或未采集，开启缓存时会明确提示本地历史不完整，要求客户端发送完整上下文，不会只发送剩余后半段。缓存保留加密内容的原字节，但无法解密，也不能保证移除加密压缩块后仍能恢复隐藏信息。外部 Conversations 对象仅凭 ID 无法在本地重建。回复观察仍有独立的大小限制，未完整采集的响应在设置页显示计数。

关闭开关停止采集和使用本地缓存，已存内容仍保留；「清空缓存」删除缓存内容和恢复索引，清空前尚未完成的响应不会重新写回。缓存使用应用私有的 `history.sqlite`，权限为 0600；它采用压缩而非额外加密，不采集认证头或供应商凭据。常规管理 `/v1` 接口只返回元数据；内置本机网页面板无需登录即可读取已保存正文，不额外脱敏。清理只影响网关的恢复能力，Codex 中的对话记录保留。

## 凭据存储

Codexpress 不使用 macOS 钥匙串保存来源凭证。新安装的本地网关把来源的 API Key 和官方 OAuth 令牌写入应用状态目录的 `credentials.json`，默认是 `~/Library/Application Support/Codexpress/credentials.json`。在「设置 → 凭据存储」查看实际位置。远端网关的管理令牌另存在 Mac 的 `remote-management.json`；远端来源的上游凭证留在服务器，不随管理目标切换。

**从旧版升级：** 原先选用「本地文件」的网关继续使用原文件（通常为 `~/.codexpress/credentials.json`），无需复制。原先使用钥匙串的，来源设置会保留，但应用不会读取、迁移或删除钥匙串条目，也不会启用以前切换存储时遗留的旧文件。请为这些来源重新填写 API Key；官方账号请重新登录。自动路由跳过缺少凭证的来源；如果固定来源缺少凭证，会等待补填，不会擅自换用其他来源。

目录权限为 `0700`，凭证文件为 `0600`。文件是明文，同一用户下运行的程序仍可能读取，请勿分享、提交到 Git 或同步。文件损坏或权限不安全时网关会报错，不会改用钥匙串。Codex 自身的认证不在此变更范围内。

## 配置和数据

- 保持一个原有 `CODEX_HOME`。管理根 `model_provider` 和新建的 `model_providers.codexpress` 连接表；直接官方登录时暂时管理官方地址覆盖及登录方式；设置模型压缩规则时，额外局部管理 `model_catalog_json`、`model_auto_compact_token_limit`、`model_context_window`，恢复时还原。
- 保留原生认证、MCP、skills、plugins、hooks、权限、项目、模型目录和历史；不改写会话数据库。
- 「恢复原连接」采用局部合并，接管期间新增的其他设置会保留；受管字段被外部修改时拒绝覆盖。「还原备份」则明确还原所选时刻的完整配置及文件认证，还原前状态也会保存。
- 上游密钥和官方凭据仅存入网关的私有文件。官方刷新后的凭据先持久化再投入使用；存储不可用会明确失败并暂停该账号。
- 应用数据默认位于 `~/Library/Application Support/Codexpress`，目录权限 0700；源元数据、管理 socket、本地访问凭据和连接快照使用受限权限。
- `usage.sqlite` 记录请求元数据、Token 与经过敏感信息隐藏的错误反馈；可关闭的原文缓存另存在 `history.sqlite`，不记录认证头。缓存输入 Token 是总输入的子集，总 Token 为输入 + 输出。
- 当前统计覆盖经过本地网关的流量；缺失或无法解析的 usage 标为不完整，可观察文字按字符估算。官方额度和重置卡属于当前客户端内部接口，接口变化时显示失败／陈旧缓存，不伪造余额。

## 管理 API

在「接入 → 管理 API」启用服务，默认端口为 **17867**，如与已配置入口冲突则首次设置时顺延。复制独立管理 Key，其他本机应用使用 `Authorization: Bearer <管理Key>` 调用页面显示的 `/v1` 基址。管理 Key 具有查询与操作权限，应按密码保管；它与聊天、图片及 Codex 网关 Key 相互独立。服务只监听本机，不通过此入口向局域网开放。

管理、聊天客户端和图片入口的启用开关即时生效；图片账号选择也直接应用。修改端口或填写新 Key 后单独点击「应用设置」；切换开关、切换账号及重新读取不会提交或清除这些草稿。读取失败可重新读取，端口占用解除后可直接重试启动。更换 Key 仍会提示旧客户端需要更新；图片设置已生效但本机接入文件导出失败时可单独重试导出。

读取接口仅查询本机状态，不查询上游：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /v1/status` | 网关、来源可用性、活跃请求、动态余额、额度、卡片、用量及核对状态 |
| `GET /v1/status?include_usage=false` | 轻量状态，保留来源、余额、额度与操作状态，省略较重的用量聚合，适合侧栏周期读取 |
| `GET /v1/sources` | 来源列表与各自状态 |
| `GET /v1/usage` | 用量汇总，支持 `days`、`source_id`、`model` |
| `GET /v1/usage/analytics` | 按日期范围查询统计与趋势 |
| `GET /v1/usage/requests` | 筛选和分页查询请求元数据，不返回对话正文 |
| `GET /v1/reconciliation` | 账单核对进度 |

操作使用 JSON 请求体。抢占、停止抢占与恢复分别调用 `POST /v1/routing/takeover`（`source_id`）、`POST /v1/routing/cancel`（当前操作 `id`）、`POST /v1/routing/recover`（`source_id`）。它们不切换 Codex 的官方／来源池连接模式。

主动更新使用 `POST /v1/refresh/balances`、`POST /v1/refresh/billing`、`POST /v1/refresh/quotas`，可传 `source_id` 限定来源；余额和额度刷新返回后台操作编号，通过 `GET /v1/operations/<id>` 查询结果。账单核对通过核对状态接口观察。主动余额刷新成功后替换动态余额基底；普通余额刷新频率保持不变。

同一来源、同一账号和刷新选项的并发请求返回同一个进行中的操作编号；上游查询不再占用路由配置锁。刷新失败和本机状态读取相互独立：操作保留 `failed`，来源快照保留旧数据及 `failure_count`、`next_retry_at`。`upstream_refresh_failed` 表示上游未取得新快照，`source_changed` 表示查询期间来源变化，`refresh_failed` 表示其他查询错误；调用方应与本机 HTTP 连接错误分开展示。

完整状态中某个附加组件无法读取时，该组件为 `null`，并通过 `component_errors` 标记；网关和其他来源状态继续返回。读取轻量状态不查询上游，也不重新聚合历史用量。

重置卡只能请求本机确认：`POST /v1/credits/reset-requests` 传入唯一 UUID `request_id`、`source_id` 及可选 `credit_id`。应用会打开确认窗口并刷新账号与卡片；点击「确认使用」前不会消耗。调用 `GET /v1/credits/reset-requests/<request_id>` 查询结果。重复同一编号不会重复消费；取消、账号变化或不确定结果不会自动换卡重试。HTTP 接口不接受直接确认或直接消费操作。

完整字段与日期分页参数见 [管理接口契约](../contracts/management.md)。重新生成管理 Key 后，旧 Key 立即失效，需要更新其他应用的配置。

### 内置网页数据面板

在「接入 → 管理 API」启用入口，点击「打开数据面板」，也可在本机浏览器访问 `http://127.0.0.1:17867/dashboard/`（端口以页面设置为准）。打开即可使用，无需密码或管理 Key。面板及数据只在本机管理端口开放，不通过 OMP／聊天客户端的局域网入口提供；其他应用调用 `/v1` 管理接口仍使用原有独立 Key。

时间、来源、模型、入口和状态选择后自动更新，关键词输入稍停后搜索，无需点击应用。支持「近1小时」「近5小时」滚动窗口，精确显示起止时间，按 5 分钟绘制趋势；刷新时窗口前移，加载更多保持原窗口，手动刷新回到新窗口的第一页，避免混用旧游标。切回日历快捷项即可编辑日期，来源等筛选保持。缓存沿用同一时间窗口，不支持的状态和关键词控件在缓存页停用，返回日志页后保留原筛选。

启用自动刷新后，前台每 **3 秒**更新统计、请求日志或缓存列表；阅读详情、加载历史分页或网页不可见时暂停。概览使用网关统计缓存，按落库序号只聚合新增记录；滚动窗口没有记录滑出时，仅补算新增及受边界移动影响的分桶。记录滑出、历史费用修正等情况重新计算，保证计数、费用和分位数准确。独立的网关诊断快照最多每 15 秒刷新一次，不阻塞统计。

- **概览与性能**：按日期范围、来源、模型、入口、结果及元数据关键词筛选，展示请求、成功率、进行中、Token、缓存命中、费用、输出 TPS、首 Token 与总耗时 P50／P95，以及每日趋势和来源／模型明细。未知计数与费用显示为未知，暂估和实际扣费分别标记；统计覆盖所选范围，不局限于当前日志页。
- **请求日志**：分页查看所有符合筛选的已保存请求，包含重试／切源的各次尝试。详情显示计时、Token、计价来源、HTTP 状态、已保存诊断和错误反馈，可切换相关尝试、继续读取长反馈并查找对应原文缓存。请求正文与成功回复不在用量日志中重复保存；没有关联缓存时明确提示缺失。
- **原文缓存**：浏览已保存的指令、工具定义、输入、输出、工具调用与结果；支持可读视图和原始 JSON，以及分块加载、复制和导出。正文按保存内容原样展示，不额外脱敏；旧错误日志写入时已隐藏的字段无法还原。加密推理／压缩项只能查看原值，不能解密。未采集、已淘汰、损坏或缺链均明确标记，不以残缺内容冒充完整历史。

新采集缓存可按日期、来源、模型、入口及关联请求筛选；旧缓存没有这些索引信息时显示「旧缓存／元数据未知」，可切换查看全部缓存。缓存采集关闭后仍可浏览保留下来的内容；网页查看不改变缓存 LRU 或触发上游查询。网页隐藏时暂停自动刷新。面板只展示网关实际保存的数据，不能读取直接官方登录流量、补回已淘汰正文或还原从未采集的内容。


## 聊天客户端接入

在「接入 → 聊天客户端」使用独立的本机／局域网入口，本机默认基址为 `http://127.0.0.1:17865/v1`。在聊天软件中选择 **OpenAI 兼容**供应商，填入页面显示的基址与「复制当前 Key」取得的密钥，随后获取模型列表。远端将 `127.0.0.1` 替换为这台 Mac 的局域网或 VPN IPv4 地址／可解析的主机名。客户端若要求完整地址，分别填写 `/v1/chat/completions` 或 `/v1/responses`。应用同时接受不带 `/v1` 的对应路径，避免部分客户端自行拼接路径时重复配置。

此入口默认随网关启动，可修改端口、关闭接入、重新生成 Key 或设置 16–256 位不含空白的 ASCII Key。它与 Codex／SSH 的端口不同，Key 也不能复用本机网关、远端机器或当前来源密钥。更换 Key 后旧 Key 不能发起新请求；已提交的请求继续。配置文件 `chatbot-access.json` 在应用私有目录中以 0600 权限保存。上游真实凭据不会返回给聊天软件。

聊天端 `GET /v1/models` 返回标准 `object: list` 和 `data[].id`，合并启用来源的能力清单，并应用模型自己的来源白名单和聊天端开关；固定来源模式只展示该来源。暂时健康状态、额度及并发不改变目录。未缓存模型目录时按来源网络策略查询，并限制查询时间与并发；空清单与查询失败分别处理。OMP 的 `/omp/v1/models` 与只读绑定按 OMP 开关返回同一组模型；Codex／SSH 主入口保留原生 `models[].slug` 格式及模型元数据，不改成聊天端的通用列表。

| 下游内容 | Responses 上游处理 |
| :-- | :-- |
| `messages`、system／developer／user／assistant 角色 | 转为类型化 `input`，保留顺序；官方源将 system 映射为 developer |
| 文本、图片 URL／内联图片、文件输入 | 规范化为 `input_text`／`output_text`、`input_image`、`input_file` |
| `tools[].function`、工具调用和工具结果 | 展平函数定义；用 `call_id` 关联调用与结果，保留参数字符串 |
| `response_format`、`verbosity`、`reasoning_effort` | 映射为 `text.format`、`text.verbosity`、`reasoning.effort` |
| `max_tokens`／`max_completion_tokens` | 映射为 `max_output_tokens`；两个设置冲突时拒绝。标准 Responses 小于 16 的正数预算提升至 16，以兼容探测请求 |
| 流式与非流式请求 | 上游统一请求 SSE；按客户端要求返回 Chat chunks、Responses 事件或完整 JSON。完整快照不重复计入已发送文本／工具参数 |
| 输入、输出、缓存与推理 Token | 使用上游完成事件中的计数，转换为对应协议的 usage；缺失计数不会伪造为已报告用量 |

官方 Codex 上游强制 `store: false` 与流式请求，保留加密推理续接所需的声明。不支持的采样参数、输出 Token 上限等从该来源的出站副本中移除；指定单个函数时，将工具集合限制到该函数，再使用 `required`，避免放宽调用范围。第三方 Responses 上游保留其扩展字段，不套用官方字段白名单。

第三方也可能转发至 Codex 后端。仅当其 HTTP 400 明确报告已知的参数校验拒绝时，同一来源最多修正三处并重试：不支持的参数、所需 instructions、store 值或已知工具选择类型。一般 400、网络超时、HTTP 5xx 和已开始输出的流不会触发这种重放。调整过的字段名称列在 `x-codexpress-adapted-parameters` 响应头，不包含参数值。

Responses 本身允许 `system` 消息。第三方代理若在 HTTP 400／422 中明确拒绝此角色（包括 `System messages are not allowed`），网关会保留指令内容，仅在发给该来源的副本中改为 `developer`，并重试一次。随后记住该来源的角色要求，后续请求直接转换，应用重启后也会保留。来源地址或认证身份变化后重新识别。

此处理也适用于 Codex／SSH 主入口和压缩端点；尚未识别的来源首次请求保持原样，换到其他来源时按其各自记录处理。不会改写本地对话，也不会根据普通错误或已经输出的响应猜测并重放。

不支持将多候选 `n > 1`、非默认 stop／惩罚／logprobs／seed 参数或音视频输出无损映射到 Responses，遇到这些请求会返回 400，不静默省略其语义。普通函数工具由聊天客户端执行，网关不代替客户端执行工具。聊天客户端端口不提供文件上传或图片生成端点，生图请使用「接入 → 图片生成」的独立入口；Responses 内置工具、文件 ID 的可用性仍取决于实际来源与模型。官方 `previous_response_id` 仅在完整本地缓存可恢复时展开历史，否则要求客户端发送完整上下文；关闭缓存后应使用完整历史请求。

客户端如能传递每条对话独立的 `thread-id`、`x-session-id` 或请求中的 `conversation_id`，网关会据此保持会话来源；未提供标识时不会凭相似内容猜测两次请求属于同一对话。不要为所有对话设置同一个固定会话 ID。

浏览器客户端可用此入口的 CORS 与 Bearer Key 认证，不使用 Cookie；浏览器或操作系统对网页访问本机网络的限制仍需由客户端满足。此端口绑定 `0.0.0.0`，允许通过 Mac 的 IPv4 网络地址访问；请求必须携带独立 Key 和正确端口，修改 Host 或转发头不能绕过认证。OMP 与聊天客户端共用此 Key，重新生成会使两者的旧 Key 一起失效。云服务器必须能通过局域网、VPN 等方式访问 Mac；SSH 只配置文件，不会自动建立推理隧道。不要将携带 Key 的 HTTP 端口直接暴露到公网，也不要复制管理 API Key 到此入口。请求沿用来源池优先级、逐源代理、会话接续与用量统计；即使 Codex 正在直接官方登录，聊天客户端仍可独立使用来源池。管理 API 与图片生成仍只监听本机。

### 终端与图形界面环境变量

可开启「接入 → 聊天客户端 → 环境变量」下的 **自动写入环境变量**（默认关闭）。开启后，应用会将聊天客户端地址和密钥写入私有的 `~/.codexpress/env.sh`（目录 `0700`、文件 `0600`），在 `~/.zshrc` 维护独立的标记区块引入该文件，并通过 `launchctl` 同步写入 macOS 图形环境；变量名固定为 `CODEXPRESS_BASE_URL` 与 `CODEXPRESS_API_KEY`，不会改写 `OPENAI_BASE_URL` 或 `OPENAI_API_KEY`。之后启动、更改聊天客户端端口或更换 Key 时会自动同步；关闭开关后自动清理受管文件、区块及图形环境变量。新终端和图形应用会自动生效，已打开的终端可执行 `source ~/.codexpress/env.sh`。本机回环 `/v1` 环境变量不会覆盖 OMP 的默认网关选择；如需为 OMP 单独指定地址，可设置 `CODEXPRESS_OMP_BASE_URL`。

协议依据：[OpenAI Responses 迁移指南](https://developers.openai.com/api/docs/guides/migrate-to-responses)、[流式事件指南](https://developers.openai.com/api/docs/guides/streaming-responses)和公开 Codex 客户端请求结构。

## OMP 一键接入

本机目标从「接入 → OMP」、远端目标从「来源池 → 本机 OMP…」点击「安装扩展」，然后重新启动 OMP。本机首次绑定请在 `/login` 选择 **Codexpress** 或运行 `omp login codexpress`；已授权的远端可直接用 `/model` 选择模型。默认绑定跟随 Mac 当前网关：本机使用 `/omp/v1/codex/responses`；独立远端使用服务器的 `/v1/responses` 和专用设备 Key。切换不需要重复登录，也不会把进行中的请求重发到新目标。

本机目标通过 `control.sock` 发现；`CODEXPRESS_STATE_DIR` 可指定其他 Codexpress 状态目录。扩展不复制固定模型清单，也不创建 `models.yml`。用 `omp --model codexpress/模型ID` 选择模型，不使用在扩展加载前验证的 `--provider codexpress`。已显式指定独立网关地址的 OMP profile 继续使用自己的连接，不跟随 Mac。

OMP 接入页提供扩展安装和登录指引。安装会复制内置发行包，不链接开发目录；OMP 未自动找到时可选择其可执行文件。本机目标的 `/usage` 展示来源余额、套餐窗口与重置卡；远端管理数据在 Mac 和 cmux 侧栏查看，OMP 不轮询服务器的管理接口。

扩展 0.1.11 修复键盘选区与 OMP 19 原生附件预览的兼容问题。粘贴图片后可在输入框上方查看附件，删除图片标记后同步隐藏，撤销后恢复；支持图像协议的终端可显示真实缩略图。

真实会话与线程 ID 独立于提示缓存 Key，重开同一会话保留线程身份；共享缓存 Key 不合并不同对话。扩展优先采用请求自身的原生 provider session ID，避免 advisor 被误归入主会话。Token 与缓存命中取自上游返回，不把本机原文缓存当作上游命中。API 来源保留原生正文、工具、加密推理项及事件；官方来源仅作其协议必需的参数适配。原版 OMP 的单次费用按宿主模型价格计算；上游实际扣费以 Codexpress 的账单核对和统计为准，不把套餐额度或余额变化当作单次请求费用。

本机网关使用 SSE，并支持 Codex V2 与 V1 兼容压缩；网关只报告结果、错误或不支持，由 OMP 决定方法顺序。独立远端网关走标准 Responses SSE，不尝试本机专用的 V2 路径。

本机目标的 `/codexpress` 支持查看状态、重新绑定、抢占、恢复及主动刷新余额、额度和账单。重置卡仍需在 Codexpress 窗口中确认；这些操作使用 Unix socket，不依赖管理 HTTP 开关。跟随独立远端时，OMP 只使用设备 Key；修改来源池请在 Mac 的远端网关界面操作。

### OMP 缓存分组与历史维护

Codexpress 0.8.5 与扩展 0.1.3 默认按当前 OMP 配置档案和工作目录生成不透明缓存分组。官方来源的出站 `session-id` 按客户端、账号、模型、速度和分组派生稳定 UUID；真实会话、advisor、线程、历史与来源绑定保持独立。正文 `prompt_cache_key`、原生 `session_id`／`conversation_id` 及元数据不改写；API／Clauder 来源不套用官方缓存头策略。

原版 OMP 18.18 可用 `omp --model codexpress/gpt-6.1-sol --prompt-cache-key codexpress-my-project` 显式指定分组；同一配置档案内相同 Key 可跨工作目录共享。关闭 OMP 提示缓存或使用空 Key 会关闭这层共享并清除该会话的压缩关联。V1／V2 压缩仅按真实会话继承普通请求分组；关联保存在最多 4096 条的内存表，网关重启后由普通请求重新建立。

工具结果的替换和裁剪会改变旧前缀。可在专用 OMP 配置档案中将 `compaction.supersedeReads`、`compaction.dropUseless` 设为 `false`，代价是保留更多旧工具输出、增大输入并可能更早压缩。这两个设置影响整个配置档案，扩展不会自动修改，也不会恢复旧工具内容或关闭正常压缩。

评估时固定上游账号、模型和速度，将首次请求、压缩后首轮与热续接分开统计。总命中率按缓存输入总数除以输入总数计算，不把合成前缀实验的比例当作日常任务保证。扩展不会添加 Codex 后台未确认支持的 `prompt_cache_options`、缓存断点或延长保留参数。

### OMP 原生绘图

在 OMP 的设置中启用 **生成图片**（`generate_image.enabled: true`）后，Codexpress 扩展可直接使用 OMP 内置 `generate_image`，不需要另一套图片供应商或 Key。绘图模型为 `codexpress/gpt-image-2`，使用同供应商的聊天模型作为 Responses 载体；支持文生图、参考图编辑与原生 PNG／WebP 返回。

请求使用同一 `/omp/v1/codex/responses` 与模型 Key。明确选择 `image_generation` 时，网关复用图片专属的官方账号选择、代理、额度与并发调度，而不是普通聊天调度；聊天额度耗尽不直接判定生图不可用，图片限流不污染聊天额度。返回原生图片项及实际图片模型、用量。原有独立图片接口、图片功能开关及指定账号继续保留；关闭图片功能或没有可用官方账号时返回明确错误。

已用模拟上游验证共享入口生图、参考图编辑、PNG 落盘及错误处理；未调用真实付费图片服务。


### OMP 压缩策略

共享窗口与压缩点从 Codexpress 同步，OMP 自定义覆盖优先；压缩开关、方法顺序及 V1／V2 许可仍由 OMP 自己管理。扩展提供 V2 `/omp/v1/codex/responses` 和 V1 `/omp/v1/codex/responses/compact` 默认端点，保留用户自定义端点。V1 JSON 与 V2 SSE 均保留原生协议及上下文，网关不自行改用生成请求或丢弃历史。

只有普通 Responses 或公开 `context_management` 的第三方服务，不一定接受 V2 的 `compaction_trigger`。实际来源明确拒绝 V2 后，网关在该来源身份下快速返回不支持，交由 OMP 按已有策略链处理；更换来源或凭据后重新判断。暂时的 429、503 和网络故障不记为不支持。

### OMP 路径显示

Codexpress 扩展不修改状态栏或安装来源显示插件。本机已有的路径显示扩展可以独立保留；账户余额、套餐额度与重置卡通过 `/usage` 查看，不在每轮结束后触发账户刷新。

本机已有的 `work-path-alias.ts` 只负责按 `~/Work` 软链接名称显示路径，独立于 Codexpress 接入；不改变真实工作目录、工具路径或会话标识。

### OMP 键盘选区

扩展同时为官方 OMP 输入框提供键盘选区：Shift 加方向键按字素或视觉行选择，Ctrl／Alt 加 Shift 与左右方向键按词选择，Shift 加 Home／End 选择到行首／行尾；终端传递 ⌘A 时可全选。扩展 0.1.9 起，终端传递 ⌘X 时可将选区剪切到剪贴板，没有选区时不剪切。Backspace／Delete 删除选区，直接键入替换，Escape 取消，普通左右键收拢选区。Ctrl+A 保持原生行首语义，不接管鼠标。

剪切、普通删除与键入替换使用原生单步撤销；剪贴板写入复用 OMP 宿主能力，包括 SSH 的 OSC 52 传输。粘贴替换保留宿主附件、折叠粘贴和菜单处理，采用删除与插入两个撤销步骤。该编辑功能不要求 Codexpress 在线，也不限定当前供应商；完整快捷键见扩展包 README。

## SSH 远端接入

此功能将远端 Codex 或官方 OMP 连接到当前 Mac 上的来源池网关，不提供远端直接官方登录。在「接入 → 远端 SSH」选择客户端：Codex 应用连接配置，OMP 安装独立扩展并绑定地址。SSH 只用于探测、安装和配置；后续推理请求直接通过网络访问 Mac。

1. **准备登录**：先在终端确认服务器主机指纹并完成密钥登录，例如 `ssh worker@server`。应用使用系统 `/usr/bin/ssh`、SSH 配置别名、ssh-agent 或指定私钥，强制检查已知主机，不接收密码、不自动接受陌生主机。远端需可通过 `python3` 启动 Python 3，首版支持 Linux／macOS 等 Unix 环境。
2. **填写连接**：打开「远端」会读取本地 `~/.ssh/config` 及静态 `Include`（支持相对路径、`~/`、绝对路径和通配路径），可在「从 SSH 配置选择」中选取明确的 `Host` 别名，配置更改后点击刷新。通配或否定的 Host 模式不列入菜单。已有保存记录的别名载入对应目录、地址、用户名、端口和私钥覆盖；新别名默认沿用系统 SSH 的设置，可手动覆盖。别名发现只解析文本，不执行 `Match exec` 或代理命令，实际连接由系统 SSH 解析配置。也可手填服务器，用户名单独填写；加密私钥需先在终端解锁。手动更换目标时不沿用上一台机器的备份和凭据身份。
3. **探测目录和地址**：点击「连接并探测」，检查远端 `CODEX_HOME` 和登录用户的 `~/.codex`。没有找到时可手填目录绝对路径，新安装的目录和配置会在应用时创建。默认本机地址取远端 `SSH_CONNECTION` 的客户端 IP；使用 NAT、ProxyJump 或端口转发时可手动填写局域网、VPN IPv4 或解析到 IPv4 的主机名。
4. **确认共用端口**：远端与本机 Codex 共用网关端口（默认 `17863`），随网关启动，不需另行开启。网关监听 IPv4 网络接口；本机凭据仅接受来自回环地址的连接，远端须使用独立机器 Key 和预览中登记的地址。伪造 Host 或转发头不能获得本机权限；管理功能仍只通过本机私有 socket 提供。旧版本若使用独立远端端口（通常为 `17864`），需重新预览并应用一次；原始备份与机器 Key 保留。更改共用端口后，也需重新应用远端配置。
5. **应用连接**：先结束远端 Codex 任务，再点击「应用到远端」，需要时可先查看预览。应用从远端直接检查网关身份和认证，不走代理、不跟随重定向；验证失败不会写配置。修改了连接或规则时会在应用时重新读取和检查；远端文件被其他程序修改时需重新读取。
6. **重启与验证**：应用完成后手动重启远端 Codex；使用 VS Code 时重载对应的远端窗口，再继续对话，在本机「用量」查看请求。现有运行进程不会热更新，仅新建对话也不会重新加载模型目录；命令行、环境变量或项目级配置仍可能覆盖用户配置。

连接设置会切换根 `model_provider` 和 `model_providers.codexpress`，其 `base_url` 使用所填地址，`experimental_bearer_token` 使用独立远端 Key，并关闭该连接的官方认证要求和 WebSocket。原模型选择、MCP、工具及其他配置保留；根级旧官方地址覆盖和强制登录方式会移除。选择「同时接入已有自定义供应商 ID」时，除内置 OpenAI／Ollama／LM Studio 外的已有定义也会指向网关。旧对话的加密上下文仍受来源兼容限制，可能触发最终兜底。已选定的 `profile` 会阻止应用，避免档案覆盖导致切换不生效。

本机已保存逐模型压缩规则时，会读取远端原有自定义模型目录或 `models_cache.json` 中的模型元数据；文件不存在时使用随应用提供的目录。生成的远端专用文件为所选 Codex 目录下的 `.codexpress-model-catalog.json`，`model_catalog_json` 使用远端自己的绝对路径，不引用 Mac 上的文件。原有自定义目录和缓存只读，模型能力和指令元数据保留；未设置规则的模型保留远端原默认值。根级全局压缩阈值和上下文窗口会转入模型元数据后移除，以便逐模型规则生效。模型目录在 [Codex 启动时加载](https://developers.openai.com/codex/config-reference/)，应用后须重启远端 Codex，之后修改本机规则也需重新预览并应用。

没有本机规则且远端从未同步过规则时，保留远端压缩设置；清空本机规则后重新应用，会恢复首次同步压缩规则前的全局设置、目录引用和专用文件状态，同时继续使用网关。专用文件原来不存在时会删除；原来已有时恢复其原始字节。新安装可从不存在的 Codex 目录或配置开始，探测和读取不创建文件，应用时才创建；还原恢复原内容及原本不存在的文件状态。

写入前，远端会在所选 Codex 目录的 `.codexpress-backups/` 下备份 `config.toml`、`auth.json`、`auth.json.bak`、专用模型目录和 `*.config.toml` 配置档案，同时记录文件原本缺失的状态。目录权限为 0700，备份、新配置与专用目录文件权限为 0600；`auth.json` 内容不会下载到本机，应用连接也不会改写它。远端配置与模型元数据只在内存中传给本机解析器，生成结果通过 SSH 标准输入发回，不放进进程参数或日志。目录、配置采用逐文件原子写入，普通写入失败尝试回滚，两份文件无法跨文件原子提交；操作前备份仍可恢复。对话数据库不读取、不修改。

「还原接入前设置」固定恢复此 Codex 目录**首次接入前**的配置、文件认证及专用模型目录，接入后自行修改的这些设置也会还原。重复应用仅新增操作前快照，不替换原始备份；还原前也会另存当前状态，连续点击还原始终回到原始设置，不会在网关配置之间切换。原始记录存放在远端 `.codexpress-backups/original.json`；旧版备份未包含模型目录时，使用首次同步压缩规则前另存的 `compaction-original.json` 记录补全其原始存在状态。即使本机仅记得最新快照，仍可在填写 SSH 连接和目录后还原。备份目录和恢复记录保留，对话文件不参与创建或清理。

升级前已应用过的机器，会检查远端最早的历史备份并验证所有记录文件的校验值。最早备份已含 Codexpress 标记、损坏、不完整或原始记录无效时，会拒绝将其他快照当作原始设置。识别采用保守规则，配置文字或注释中出现 Codexpress／远端 Key 前缀时也可能要求手动核对备份；应用不会猜测或自动删掉认证字段来拼造原始配置。原始备份丢失时，不能从当前网关配置反推出旧 URL 和密钥。

应用不会自动终止远端 Codex，请在还原前结束任务、还原后重启。「撤销 Key」使后续请求认证失败，不自动还原远端配置；重新预览可生成新 Key。远端不再有独立开关；要停用某台机器，请撤销它的 Key。

### 云服务器／远端 OMP

1. 在「远端 SSH」选择 **OMP**，填写 SSH 连接并点击「连接并探测」。远端需已安装官方 OMP、Bun 和 Python 3；无需安装自定义 OMP。探测遵循 OMP 的 profile、`PI_CODING_AGENT_DIR`、`PI_CONFIG_DIR` 目录规则，默认 `~/.omp/agent`，也可手填远端绝对路径。
2. 填写**远端可访问的 Mac 局域网／VPN IP 或主机名**，不要使用 Mac 的回环地址。点击「读取扩展状态」可查看远端 OMP 版本、扩展版本和已保存地址；读取不要求已有配置文件、默认模型或已启用客户端入口。
3. 点击 **安装扩展并连接**；已安装时显示 **安装／更新扩展**。应用启用共用客户端入口，使用其当前端口（默认 **17865**）构造 `http://所填地址:端口/omp/v1`，先从远端验证连接，再传输应用内置扩展包，调用远端原生 `omp plugin install` 和 `omp login codexpress`。Key 由 OMP 自己保存，不写进地址配置或命令参数。
4. 首次安装后重启远端 OMP，在 `/model` 中选择 `codexpress/模型ID`。新安装没有 Agent 目录或配置文件也可接入，无需先填写默认模型；不生成受管 `models.yml` 或 `config.yml`，模型及压缩策略在 OMP 中管理。
5. Mac 的 **IP、主机名或共用端口变化**后，修改地址并点击 **更新连接地址**，无需重新安装扩展。应用显示已保存地址和待更新提示。正在运行的 OMP 在下一轮请求读取新地址；默认 V1／V2 压缩端点随之更新，显式自定义端点和启用开关保持不变，会话、历史和缓存标识不重建。远端设置了 `CODEXPRESS_BASE_URL` 时环境变量优先，界面会提示同步修改；应用不改写远端 shell 配置。

扩展包保存在远端 Agent 目录的 `.codexpress/packages/` 下，供原生插件安装持续引用；不要手动删除正在使用的包。重复安装更新扩展，不重置其他供应商或用户配置。若检测到旧版 Codexpress OMP 接入快照，会先撤回旧受管 YAML 配置，再切换扩展，保留原始备份和用户自己的设置。OMP 认证由原生登录流程维护；应用不下载凭据或历史。

OMP 使用共享客户端 Key，没有逐机器撤销按钮；关闭聊天客户端入口会停止全部客户端接入，重新生成 Key 后需重新绑定仍允许访问的客户端。远端管理 API 仍需另行建立 SSH 隧道，模型接口不开放管理权限。

已在隔离目录中使用官方 OMP 18.16 验证实际扩展安装、原生登录及同一运行会话内的 IPv4／IPv6 地址切换；普通请求和默认压缩端点更新，历史、会话与缓存标识保留。原生界面已验证读取状态、启用入口和更新已保存地址。验证使用模拟上游及本地 SSH 传输替身，未连接真实云服务器，未调用付费上游。

**网络要求**：当前远端入口为明文 HTTP，仅适合可信局域网或 VPN。SSH 加密覆盖配置操作，不覆盖后续 HTTP 推理；本功能不自动开通防火墙、路由器端口映射或 SSH 隧道，也不应直接暴露到公网。本机休眠、退出 Codexpress 或网络变化会使远端连接中断，需保持 Mac 和网关运行。SSH 操作超时若发生在应用或还原阶段，请重新读取配置核对状态，远端备份仍保留。

## 兼容范围

- Codex／SSH 入口使用原生 Responses HTTP/SSE，请求体与响应正文尽量按原字节转发。独立聊天客户端入口提供 Chat Completions／Responses 兼容转换；没有 Anthropic 协议转换。
- 第三方支持 `/responses`、`/responses/compact` 和 `/models` 路径；官方支持 Responses 生成／压缩、模型目录及认证／额度／重置卡链路。其他端点明确报错；实际可用能力取决于账号、模型与上游接口。
- 受管 provider 关闭 WebSocket，使用 SSE。工具是否受支持仍取决于上游模型与接口。
- 只覆盖系统代理模式；Clash TUN／透明代理关闭。应用不能凭一个网络选项绕过 TUN。
- `previous_response_id`、已识别密文／上游状态绑定原来源；完整可移植历史在原来源不可用时可迁移，成功后保持新来源。不会把生成到一半的结果拼接成另一来源的回复，也不会盲目重放结果不明的生成。
- 识别 Codex 的 `thread-id`／`session-id`，工具执行后的请求沿用已知来源；同一客户端的不同线程互相隔离。HTTP 及 `response.metadata` 中的路由标记原样转发，内部只存摘要，不受短响应 ID 的长度限制。
- 普通线程／模型偏好会持久保存；响应 ID、密文及路由标记的硬绑定仍在内存中。网关重启或绑定淘汰后，已确认的旧供应商仍能回到原来源；无法确认时按最终兜底规则处理，关闭兜底才保留 409。
- 已有自定义供应商 ID 的兼容连接须重新应用配置并重启 Codex 后生效。内置 OpenAI／Ollama／LM Studio ID 不会被改写；正常路径不将原源专属密文发往其他来源；最终兜底会明确降级并通知，且不修改本地历史。
- 压缩响应及超大单个观察事件仍按原字节转发，但 Token 采集可能不完整。

当前构建使用 ad-hoc 签名，尚未 Apple 公证。首次配置后，请确认模型列表、额度查询及新旧对话在所用账号和客户端上可用。

## 构建与检查

需要 Xcode/Swift 和 Rust stable。若项目内 `.tools/` 已安装 Rust，脚本会自动使用；否则使用 PATH 上的工具链。

```sh
bash scripts/check.sh
swift test
bash scripts/build.sh
```

完整工具续接的本地回归检查使用真实 Codex、临时配置目录及模拟上游，不访问真实账号：

```sh
python3 scripts/check-gateway-continuation.py
```

可用 `--codex /path/to/codex` 检查桌面端内置版本。

构建脚本编译 release Rust 和 Swift arm64，生成原生图标，打包并 ad-hoc 签名 `dist/Codexpress.app`。

开发时可通过 `CODEXPRESS_STATE_DIR` 指定隔离状态目录，通过 `CODEXPRESS_GATEWAY_PATH` 指定 helper。状态目录路径需足够短，满足 Unix socket 的系统路径长度限制。helper 启动参数：

```sh
codexpress-gateway --state-dir /absolute/private/path --port 17863
```

自动测试使用临时目录和本地模拟上游／代理，不消耗真实额度或重置卡。
