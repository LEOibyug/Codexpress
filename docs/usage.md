# 使用指南

[← 返回项目首页](../README.md)

## 使用

从 [Releases](https://github.com/LEOibyug/Codexpress/releases/latest) 下载 DMG，打开后将 Codexpress 拖入「应用程序」。支持 Apple Silicon Mac，要求 macOS 14 或更新版本，无需安装开发工具。

当前版本使用临时签名，尚未经过 Apple 公证。首次打开若被系统拦截，请先尝试打开，再前往「系统设置 → 隐私与安全性」选择「仍要打开」。

从源码构建的应用位于 `dist/Codexpress.app`，可双击打开，或执行：

```sh
bash scripts/run.sh
```

首次启动会打开设置窗口，之后常驻菜单栏。可以把应用移到 `/Applications`；应用与网关必须作为完整 `.app` 一起移动。

1. 在「来源」添加原生 Responses API，填写基址和密钥后自动获取模型列表，也可切换为手动填写。默认强制直连，不继承系统代理或代理环境变量。
2. 添加官方账号时只需填写本地 Clash 的 HTTP／混合代理端口（例如 `7890`），保存后点击「登录」。应用使用 `http://127.0.0.1:端口`；已有本地 SOCKS 配置编辑端口时保留协议。授权网页由系统浏览器打开；浏览器网络遵循浏览器设置，应用侧的令牌交换、刷新、模型获取、额度查询和生成均使用该源指定代理。
3. 在「路由」调整优先级，或固定一个来源。新对话优先使用排在前面的兼容来源，连续对话沿用已成功连接的来源；识别到拒绝／限流时按规则转给下一来源。指定代理失效不会悄悄直连。
4. 在「设置」核对 Codex 配置目录，点击「预览连接配置」，审阅后点击「接管」。这一步必须由用户主动执行，应用启动时不会修改 Codex 配置。
5. 在 Codex 中新开会话验证连接。预览中可为已有供应商选择原 API 来源，并确认同一账号和密钥。只有已确认的 ID 接入网关，旧上下文优先回原来源；未确认的连接保持原样，原定义保存供还原。应用后需重启 Codex，已运行的会话连接不会热更新。

退出应用会停止网关，Codex 的本地连接保留。有请求正在进行时，菜单栏「退出」、⌘Q 等正常退出操作会先弹窗确认，默认选择「继续运行」；确认「仍然退出」后才停止网关。退出前无法获取活动状态时也会提示确认。仅关闭设置窗口会继续在菜单栏运行。需要恢复原供应商时，先在设置中选择「恢复接管前连接」。已接管期间不能更改端口；恢复后修改端口、重启，再预览和接管。

## 直接官方登录

菜单栏面板、来源页及「设置 → Codex 连接」提供「直接官方登录」。点击后自动检查配置、等待 Codex 正常退出、切换到内置 OpenAI 提供商，并重新打开 Codex。复用 Codex 自己保存的 ChatGPT 登录；尚未登录时，在 Codex 原生界面完成授权。Codexpress 的来源池账号不会被复制进 Codex 的认证文件或钥匙串，两个客户端继续各自管理令牌。

此模式下 Codex 使用正常的系统网络和系统代理，不使用来源里填写的 Clash 端口。Chat、绘图和网页会话等原生功能由 Codex 版本及登录账号提供，本工具不实现这些功能。原生流量不经过本地网关，因此不参与优先级切换，也不计入逐源 Token 统计。需要返回时点击「使用来源池」，同样自动重启 Codex。

直接官方模式明确固定官方 Responses／ChatGPT 服务地址及 ChatGPT 登录方式，并启用系统代理。旧会话可能仍选择原供应商 ID，因此此模式会暂时把已声明的供应商 ID 指向官方地址并改用官方认证，完整原表保存在私有快照，返回号池时恢复。工具、历史及来源池设置保留，不改写会话数据库。启动时还会覆盖桌面端的服务地址环境变量、清空继承的 API Key／外部服务入口，并使用新建的本地 app-server，避免复用旧后台连接。系统代理环境不改动。

切换前自动备份认证文件，官方登录后即使 `auth.json` 被原生客户端重写，返回号池也会恢复号池模式下的认证文件；再次进入官方模式则恢复该模式上次保存的文件认证。Codexpress 来源池自身的 API 密钥由所选凭据存储管理，独立于 Codex 的认证。旧版本已经丢失且没有备份的 Key 无法自动重建，需从已有备份恢复或重新填写。

切换中的退出提示由 Codex 处理，30 秒内未退出则停止操作，不强制结束进程、不写入连接配置。受管字段已被外部修改，或当前配置档案覆盖连接／登录方式时，提示处理冲突后重试。管理员策略仍可能优先，旧会话的模型及运行时状态仍需在客户端核对。

## 配置与认证备份

点击「应用连接设置」、直接官方登录、切回来源池或恢复原连接时，先保存当时的 `config.toml`、`auth.json`、`auth.json.bak`、同目录的 `*.config.toml` 配置档案及本应用连接快照。设置中的「配置备份」可按时间选择「还原备份」；确认后正常退出 Codex、还原所选文件并重启。还原前会再备份当前状态，所以可以选择该备份撤回还原。

备份保存在应用数据目录的 `configuration-backups/`，每份独立保存，目录权限 0700、文件权限 0600；查询界面不返回认证内容。恢复前验证文件校验值，损坏、跨目录或符号链接的备份拒绝覆盖。完整备份还原会恢复配置文件到选定时刻，保留历史和其他非配置数据；「恢复原连接」仍采用受管字段合并。文件中不存在的认证也会按当时状态恢复。备份不包含其他应用的钥匙串内容，钥匙串登录需由 Codex 自身确认。备份失败会阻止本次配置写入。

## 供应商模型列表

来源编辑页默认选择「自动获取」。第三方通过 API 基址下的 `GET /models` 获取；基址以 `/responses` 结尾时使用同级 `/models`。支持 OpenAI 的 `data[].id`、Codex 的 `models[].slug` 及模型 ID 数组。官方账号登录后通过官方 Codex 模型目录获取。获取操作使用来源自身的网络策略，代理失败不会改用直连，不转给其他来源，也不计入生成用量。

成功结果去重后保存在来源设置，并用于模型路由。启动后、来源保存及登录后自动刷新，运行期间每小时更新已启用来源，也可点击「刷新模型」。失败时保留上次列表并显示错误；未获取到列表时仍沿用空列表不限模型的既有规则。供应商不支持查询时可切换为「手动填写」，旧版本中非空的手动模型列表不会被自动覆盖。

未保存的新 API 来源也可获取模型，密钥仅暂时发送给本机网关，保存来源时才写入所选凭据存储。编辑已有来源的 API 地址后，自动获取需要重新填写密钥，避免在未保存时把原密钥发往新地址。官方账号修改代理后先保存，随后按新端口获取模型。旧的远程代理配置会保留，填写本地端口后才改用本地代理。

## 按模型自动压缩上下文

在「设置 → 按模型自动压缩上下文」添加模型 ID、压缩阈值（Token）和可选的上下文窗口。例如，一个模型达到 180000 Token 时压缩，另一个达到 45000 Token 时压缩。同一模型在官方／API 来源间共用规则，客户端按模型元数据选择阈值。

点击「保存模型规则」，再「预览连接配置」及「应用连接与模型规则」。已经接管连接也可以直接更新规则，无需先恢复。完整退出并重开 Codex 后可继续原对话，无需删除或新建对话。使用 VS Code 时，重载对应的本地／远端窗口以重启扩展的 Codex 后台。模型目录在进程启动时加载，仅更新文件或在同一后台中新建对话不会刷新；已运行会话仍保留旧模型参数。删除规则后再次应用可恢复对应默认值，删除全部规则或恢复接管前连接会还原原有模型目录及全局上下文设置。

规则通过 Codex 的 `model_catalog_json` 加载。优先基于原有自定义目录，其次所选目录的模型缓存，否则使用随应用附带的 Codex 0.162.1 模型元数据。原模型指令、能力和未知字段保留；原全局窗口和压缩阈值移入已知模型元数据，避免覆盖逐模型规则。生成的目录是静态快照，模型能力更新后需重新应用规则；配置 profile、命令行参数或客户端设置的显式覆盖仍可能优先。未知模型使用 Codex 的保底元数据，建议填写供应商实际窗口。模型 ID 的版本后缀匹配遵循 Codex 自身规则。

生成目录同时兼容较旧的 Codex：对缺少 `base_instructions` 的条目，从现有 `model_messages.instructions_template` 补齐旧版必需字段，已有值及新版元数据保留。之前应用的目录不会随 Codexpress 升级自动改写；本机和远端都需重新预览并应用，远端完成后再重启其 Codex 后台。

压缩阈值不能超过上下文窗口的 90%；窗口值应与上游真实能力一致。压缩由 Codex 发起，正常路径继续透传，网关不自行生成摘要；下述最终兜底仅在无法续接时按明确设置移除请求副本中的加密状态。当前自定义 provider 的 CLI 通常通过 Responses 生成摘要；客户端使用 `/responses/compact` 时也支持转发，包括官方源的指定代理。官方真实账号压缩仍需实测。

## 官方额度与重置卡

打开来源页或展开菜单栏面板时，会刷新其中已启用来源的账户信息；后台每 30 分钟低频更新一次。官方额度短时间重复打开会合并查询，距上次查询不足 15 秒时使用缓存。菜单栏和来源卡片同时显示短周期及每周剩余百分比、各自的重置时间。按接口返回的时长识别每周窗口，缺失值显示「未知」；查询失败保留上次数据并标注「更新失败」。

重置卡随账户信息刷新按需查询，5 分钟内复用已有结果，不另设后台轮询。手动「刷新额度」及使用重置卡前会一起更新额度和卡片。

在官方来源卡片里展开重置卡列表。使用前刷新卡片和额度，确认账号／工作区、卡片及到期时间，再手动提交。应用不会自动消耗卡片。

操作在提交前持久化稳定 ID，并绑定确认的账号。重复点击不重复提交；网络结果不明时保留「待核实」，只重新查询卡片和额度，不自动重放消费请求。重置成功后刷新额度，并在确认恢复时解除该来源的额度耗尽限制。累计 Token 统计保留。

## 自定义来源余额

编辑自定义来源时可开启「余额不足时通知」并填写预警余额，单位跟随供应商返回的币种。余额达到或低于阈值时发送系统提醒，例如「Clauder 余额不足，当前余额 US$ 9.50」。低余额期间只提醒一次，重启应用也不会重复；充值恢复到阈值以上后，再次不足时可重新提醒。查询失败、过期数据或无法获取余额不会触发预警。关闭预警不影响余额查询，也不会停用来源。

来源卡片与菜单栏面板只展示剩余可用余额；刷新期间保留旧金额，并显示小型加载符号。首次查询中显示「查询中…」，接口不支持或全部查询失败时显示「无法获取」。已有余额更新失败时保留旧金额，并用时钟标记提示查看上次更新时间。停用的来源不主动查询。

设置预警余额后，余额高于预警值 5 倍显示绿色，高于 1 倍且不超过 5 倍显示黄色，达到或低于预警值显示红色；未设置预警值时使用中性色。官方剩余额度高于 30% 显示绿色，高于 10% 且不超过 30% 显示黄色，10% 及以下显示红色。颜色不影响来源优先级或自动切换规则。

来源正在处理请求时，状态绿点闪动；网关有进行中的请求时，菜单栏图标右下角显示绿点。活动状态约每秒更新，闲置对话不持续点亮；开启系统「减少动态效果」后，来源绿点保持常亮。

打开相关界面时按需刷新，另外每 30 分钟后台更新一次。查询成功后 15 秒内复用结果，失败后 60 秒内不重复探测；同源并发请求合并。优先复用已识别的余额协议，Claude Code Hub 临时登录会话只保存在内存中，过期或认证失效后重新获取。

支持 Claude Code Hub、New API／One API、Sub2API 钱包或密钥总额度、OpenAI 兼容余额接口，以及 DeepSeek、Moonshot、SiliconFlow、OpenRouter 的常见钱包格式。接口返回总额度与累计已用时，转换为剩余额度；不把每日／每周限额、无限额度哨兵或缺失数据当作余额。优先显示账户总余额，只能获取密钥总额度时显示该密钥的可用余额，悬停可查看范围。New API 标准 quota 单位按 500,000 quota = 1 USD 换算；不同币种不做无依据的合并。

仅访问来源自身的站点与路径，沿用该来源的直连／指定代理规则，不跟随重定向、不向第三方探测服务发送密钥。查询不发起模型生成，也不改变来源优先级或可用状态。

## 官方账号图片生成

在「来源」登录官方账号后，打开「图片生成」。生图使用独立的本机端口（默认 `17866`）与独立 Key，沿用官方来源的指定代理，消耗该账号的套餐额度。可按官方来源优先级选择账号，也可指定一个账号；此选择独立于文字对话的固定来源设置，停用、额度耗尽或需要登录的账号不会参与分配。

点击「复制接入提示词」，将内容发给本机 Codex 或其他 Agent。Skill 和 Python 3 调用脚本随 `.app` 分发，无需另外安装到 Codex 目录。提示词只包含应用内 Skill 路径及私有配置路径，不包含密钥；配置保存在 `~/.codexpress/image-client.json`，文件权限为 `0600`。在本页更改端口或重新生成 Key 后，已导出的配置会同步更新。将应用交给其他用户时，由对方登录自己的账号并复制自己的接入提示词。

其他支持自定义 Images API 地址的 Skill／客户端，可填写本页的 API 基址和独立 Key。支持 `/v1/models`、`/v1/images/generations` 和 `/v1/images/edits`，模型为 `gpt-image-2`，返回 PNG 的 `b64_json`。编辑支持 JSON 内嵌图片及 OpenAI SDK 常用的 multipart 图片上传，最多 5 张 PNG／JPEG／WebP，每张 10 MB、合计 32 MB；不支持远程图片 URL、mask、流式输出及 JPEG／WebP 输出。尺寸与质量以官方账号实际支持为准。

脚本的 `check` 命令只检查接入与模型列表，不生成图片。生图超时、连接中断或服务端错误时不自动重放，结果未知的请求可能已消耗额度；使用其他 SDK 时也应关闭自动重试。明确收到 429 拒绝时，自动选择模式可尝试下一个可用官方账号。请求会出现在用量记录中，未返回图片 Token 计数时不按图片 base64 大小估算文字 Token 或输出 TPS。

## 应用内反馈

设置窗口的操作反馈固定显示在左下角，不随页面滚动。普通提示约 5 秒后消失，错误约 10 秒后消失；鼠标悬停暂停计时，可手动关闭或右键复制内容。来源文件损坏、配置未同步等持续状态保留明确提示。菜单栏中的连接切换按钮右对齐；直接官方登录时原位显示「使用 API 模式」，返回来源池后显示「直接官方登录」。

## 连续对话与余量保护

编辑任一官方或第三方来源，可开启「限制活跃对话数」，设置对话上限和空闲释放时间。默认不限制；开启时预填 3 个、15 秒，可按供应商实际承载能力调整。正在请求或接收回复的对话一直占用名额，不会因持续时间较长而过期；最后一个请求结束后保留设定的短窗口，同一线程和模型的后续请求复用名额。不同模型分别计数，无线程标识的请求分别占用名额。

名额已满时，自动模式会为其他对话选择下一个可用来源；固定来源模式不会绕过限制。来源页和路由页显示当前占用与上限。这一短窗口只用于限制活跃对话，与来源粘性、缓存闲置回切及官方余量保护的时间独立。

「路由 → 官方余量保护」默认阈值为 **10%**，可调整。短周期或周额度任一已知剩余不高于阈值，且该官方账号已有活跃对话时，新对话改分配给其他可用来源；原对话继续使用该账号。活跃指最近 30 分钟有成功请求或仍在接收响应。没有活跃对话时允许接收一个新对话，并发请求也受此限制；同一账号配置成多个来源仍共用保护。

任一主额度归零便跳过官方来源；查询失败或缺失窗口时保留此前已知低／零余量，收到明确恢复数据后才解除。已转到其他来源的对话在活跃期间继续沿用新来源；新对话仍按优先级分配。固定来源模式保持用户选择，不自动跨源。

「路由 → 对话接续 → 闲置回切时间」默认为 **30 分钟**，可选 15 分钟至 24 小时或关闭。从最近一次成功请求结束计时；仍在接收回复时不会到期。闲置到期后，下一次请求按当前排序选择更高优先级的可用来源，官方与第三方 API 使用同一优先级规则；只有回切目标本身为官方账号时，才额外要求明确的正余量并遵守余量保护。工具结果接续和上下文压缩保持当前来源。回切失败不替换已确认的来源；仅在能安全重试的失败下尝试当前来源，提交结果不明或已开始输出时不重放。

停用的来源不再参与新的分配，已有绑定也不能绕过停用开关。请求若仍在等待 OAuth 或准备上下文，期间变更开关、排序或路由设置，会在提交前放弃旧选择并重新规划。已经开始向上游提交的请求及正在返回的流保持运行。此规则用于来源池模式；「直接官方登录」由 Codex 原生连接，不受池内排序控制。

连续对话按线程和模型建立来源偏好，网关重启后保留活动时间和来源，最多保存 100000 项。闲置到期仅开放回切机会，不删除来源绑定或原文缓存。只在本应用私有 `affinity.sqlite` 中保存摘要、来源身份及活动时间，不读取 Codex 历史。请求的 `prompt_cache_key`、正文与上游路由标记原样保留；来源身份变化使旧偏好失效。不能跨源使用的服务端状态仍受下述兼容边界限制。

## 旧对话接续与最终兜底

本地找不到对话 ID 的映射，不代表上游的 ID 已失效。没有明确来源绑定或加密状态约束的 ID，网关会先保留原 ID，按线程来源线索、优先级尝试上游；只有收到明确拒绝才试下一来源，最多尝试 5 个来源。已知来源绑定或加密状态仍遵守原来源约束。上游明确拒绝 ID 或加密状态后，可恢复完整缓存上下文并在同一次客户端请求内交接，避免反复消耗 Codex 的重连次数。HTTP 错误与尚未输出内容的 SSE 失败均可触发这一流程；已产生输出、提交结果不明或普通服务端错误不会因此重放。

设置的连接预览提供「已有对话的原来源」。确认原供应商与来源池中的 API 使用同一账号和密钥后，旧对话可以通过专属本地凭据回到原来源，保持正文及加密上下文。地址、密钥或配置目录变化后需重新确认；未确认的旧供应商连接保持原样。

「路由 → 对话接续」默认启用最终兜底。原来源无法续接、未知状态被本地拒绝，或上游明确拒绝且另有可用来源时，网关最多尝试一次重建：移除本次请求的加密推理／压缩块及旧响应／会话／轮次状态引用，保留可见历史和工具结果，再按正常规则分配。隐藏推理或压缩摘要可能缺失，因此它是尽力恢复，不是无损迁移。已开始的流及提交结果不明的请求不会自动重放，固定来源模式仍不跨源。

触发时发送系统通知；官方来源变为额度耗尽时也通知一次，恢复后再次耗尽可再通知。首次需在 macOS 允许 Codexpress 通知；拒绝权限时，应用内显示同批提示。降级成功后只持久化已排除状态的摘要，后续保留新来源的有效加密内容，并在闲置保护期内继续留在新来源。闲置回切涉及旧上游状态时，也经过此重建流程；关闭最终兜底或启用原文缓存但缺少完整历史时，继续沿用当前来源。没有删除或改写本地对话。

## 官方来源的网络状态

来源池中的官方账号使用该来源指定的本地代理端口；「直接官方登录」使用 Codex 自身的网络路径。TUN 接管的是网络路由，不会自动替代来源里填写的 HTTP 代理端口。因此，原生登录可用并不能证明指定端口的代理握手和上游连接也可用。

网关按来源及网络策略复用 HTTP 连接，减少重复的代理隧道与 TLS 握手。修改来源地址或代理后使用独立连接池；官方来源不会因代理失败改为直连。空闲连接最多保留 60 秒，最多缓存 256 组来源连接池。

连接失败会让该来源短暂冷却 15 秒，并影响分配到同一来源的其他对话；429 等响应按各自冷却规则处理。错误提示区分连接建立超时、连接建立失败、请求超时和数据传输中断。连接建立阶段仍可能涉及 DNS、代理隧道和 TLS，单条提示不能确认是哪一个环节。

官方额度查询成功后，会清除查询开始时已有的临时代理故障。查询期间新发生的故障不会被旧查询结果覆盖；认证失效、HTTP 限流和额度限制保持独立。额度查询失败则保留旧快照和故障信息。

## 实时用量与费用统计

用量页打开时每秒刷新，连接和流式接收中的请求立即显示，完成／失败后进入历史列表。支持按 24 小时、7 天、30 天、来源和模型联合筛选，最近 200 次上游尝试分页展开；自动回退会记录各次尝试。顶部汇总参考费用、总 Token、请求、平均输出 TPS、均次费用、缓存节省、成功率和耗时；下方展示费用构成及模型／来源排行，可按费用、Token 或请求数排序。点击排行可筛选明细，汇总覆盖所选时间内的全部记录，不受 200 条明细限制。

每条记录展示输入、输出、缓存命中、缓存写入和推理 Token。上游计数优先；缺失的输入或输出按字符估算，并以 `≈` 和「字符估算」标明，后续获得计数时替换。中文等约 1 字符/Token，其他文字约 4 字符/Token；图片、音频、文件及加密内容不纳入字符估算，无法观察的输出保持未知。缓存和推理数值只使用上游报告。

输出 TPS 使用输出 Token 除以请求总耗时，包含首 Token 等待，不计输入 Token。模型／来源平均值按已成功完成且有输出计数的输出总量／请求总耗时加权；一次性 JSON 与保留了耗时的旧记录也可计算，无有效计数或耗时则显示 `—`。详情另列「传输阶段」速度，从首个流式文字／工具参数计时到终止事件；上游缓冲后集中返回时，此值可能很高，不能代表模型真实生成速度。例如输出 375 Token、耗时 18.179 秒，输出 TPS 为 20.63，即使最后 342 毫秒集中传输，也不会显示为 1096 TPS。成功率不包含进行中请求；缓存命中率只使用有明确输入和缓存计数的样本。

流式响应的详细计数通常在响应结束时到达，接收期间可能先显示估算值。此前未采集到且未保存正文的详细计数无法补算。

请求结果以已观察到的结束事件为准：收到 `response.completed` 后，客户端关闭流不会把“完成”改为“已中断”；明确的上游失败保留“失败”。没有完整结束事件便提前断开的响应仍为“已中断”。Token 计数是否完整单独标记，缺少 usage 不代表请求中断。旧版本留下的误标记录不会仅凭连接状态自动改判。

## 参考费用与价格表

用量页的「API 价格表」列出内置的 OpenAI 官方价格、核对日期及原始链接。当前版本核对于 **2026-10-21**，单位为 USD／百万 Token。来源无论是官方账号还是第三方 API，都使用这张表折算参考费用，便于比较使用量；金额不代表 ChatGPT 订阅扣费或第三方实际账单，不包含工具调用、图像、音频、税费与地区附加费用。

每次请求分别计算非缓存输入、缓存读取、缓存写入和输出费用。缓存读取及写入是输入 Token 的子集，计价时从非缓存输入中扣除；推理 Token 属于输出，不重复加价。响应中的实际模型及服务等级优先于请求声明，未收录模型、未知计费模式与缺失计数单独标明，不当作免费请求。缺少缓存计数时按未命中估算；缺少输出或缓存写入价格时只计算已知部分。Fast／Priority、Ultrafast、Flex／Batch 仅在已收录对应价格时计算。

[官方 API 价格表](https://developers.openai.com/api/docs/pricing)仍区分部分模型的长上下文计价。例如 GPT‑6.1 Sol 输入超过 **272,000 Token** 后，整条请求的输入／缓存按 2 倍、输出按 1.5 倍折算。部分模型官方按整段会话判断长上下文，本应用按每次请求的输入量近似，详情会标明这一限制。

[Tibo 于 10 月 12 日说明](https://x.com/thsottiaux/status/2109430894604026039)，从订阅额度消耗的 GPT‑6.1 Sol 不收长上下文费用。因此官方账号的该模型按基础单价参考折算。第三方来源可在「编辑来源 → 费用估算」开启「订阅来源」，开启后该来源所有模型均免长上下文加价，其他服务等级倍率仍按已知价格计算。此开关不改变供应商的真实收费。新版请求使用发生时的计价快照；旧版本记录按来源当前设置补算。

新版每条请求保存价格版本、计价模型、来源计价方式、有效单价及费用分项，修改来源或升级价格表不会重算这些快照。旧版本记录使用当前价格表补算，并标记「历史参考价补算」；来源仍存在时，按它当前的类型及「订阅来源」开关计价，之后修改开关也会重新计算这些旧记录。已移除来源保留上次补算结果；无法匹配来源时按 API 参考价计算并标明来源类型未知。历史未采集的详细 Token 不能补齐。总计与均次费用只包含可计价部分，旁边展示已计价覆盖数、未收录、部分计价及无有效计数的数量。

## 本地原文缓存

「设置 → 本地原文缓存」默认启用，容量为 **5 GB**，可调整为 0.064–1000 GB。它只保存启用后经过网关、成功完成且已完整观察的 Responses 输入和回复，包含工具调用、工具结果以及该请求的指令和工具定义。不会读取 Codex 历史库或补齐启用前的内容。直接官方登录的流量不经过网关，不会采集。上游的 `store: false` 控制上游存储，本地是否缓存由这里的开关决定。

内容按 JSON 项切分为最多 64 KiB 的增量块，去重后压缩保存。重复历史通过共享块和顺序引用复用；再次使用或读取某个块时更新该块的最近使用时间。容量不足时按块淘汰最久未使用的内容，不按整条对话删除，也没有固定的 30 天过期规则。容量上限包含缓存数据库中的压缩内容与索引，SQLite 写入和清理时可能短暂使用额外的事务日志空间。

需要放弃旧 `previous_response_id` 并重建请求时，网关可从完整缓存链补齐此前输入和输出，再附加本轮新增内容。认证范围和线程之间隔离；工具调用与结果保持原有顺序和配对。该操作仍遵守来源路由和最终兜底设置，不会重放已经开始输出或提交结果不明确的请求。

若任何必需块已经淘汰、损坏或未采集，开启缓存时会明确提示本地历史不完整，要求客户端发送完整上下文，不会只发送剩余后半段。缓存保留加密内容的原字节，但无法解密，也不能保证移除加密压缩块后仍能恢复隐藏信息。外部 Conversations 对象仅凭 ID 无法在本地重建。超出观察或恢复大小限制的内容不保证可恢复，未完整采集的响应在设置页显示计数。

关闭开关停止采集和使用本地缓存，已存内容仍保留；「清空缓存」删除缓存内容和恢复索引，清空前尚未完成的响应不会重新写回。缓存使用应用私有的 `history.sqlite`，权限为 0600；它采用压缩而非额外加密，不保存认证头或供应商凭据，也不会通过管理接口返回正文。清理只影响网关的恢复能力，Codex 中的对话记录保留。

## 凭据存储

「设置 → 凭据存储」可选择 **钥匙串**（默认）或 **本地文件**。仅由网关进程访问持久化凭据；界面使用内存快照。每个已存在或缺失的来源凭据在网关进程中缓存，重复轮询不会再次读取钥匙串；官方登录及刷新先保存新令牌再用于请求，界面收到更新时再获取持久化快照。

钥匙串模式沿用 Codexpress 自己的服务项。当前本地构建使用临时签名，每次更新后程序的签名身份可能变化；macOS 仍可能要求为网关逐项授权，不能保证跨版本完全免提示。应用不会放宽钥匙串访问控制或访问其他应用的凭据。

本地文件模式将来源池的 API Key 和官方 OAuth 令牌写入 `~/.codexpress/credentials.json`，包括之后刷新的令牌。目录权限为 0700，文件为 0600；它是**明文存储**，同一 macOS 用户的其他程序也可能读取，请勿分享、提交到 Git 或同步该目录。此模式不再访问钥匙串；来源设置、统计、原文缓存和配置备份仍位于应用数据目录，Codex 的 `~/.codex` 和认证保持原有管理方式。隔离开发实例使用其状态目录内的 `.codexpress/`，不会共用生产文件。

切换时先收集现有凭据、复制到目标位置并逐项校验，最后保存存储选择；任何一步失败都不启用新位置。迁移与官方刷新串行，迁移期间新请求可能短暂等待，已启动的网关不会重启。首次从钥匙串迁移仍可能需要授权读取已有项。存储选择保存在应用目录的 `credential-storage.json`，重启后沿用；文件损坏、权限不安全或是符号链接时明确失败，不静默回退到另一个位置。

原存储位置的副本会保留，供迁移确认与恢复使用，后续更新只写入当前选择的位置。切回钥匙串后，`~/.codexpress/credentials.json` 仍可能包含旧的明文凭据；确认钥匙串模式正常后，可自行清理该副本。删除来源也仅删除当前存储中的凭据。

## 配置和数据

- 保持一个原有 `CODEX_HOME`。管理根 `model_provider` 和新建的 `model_providers.codexpress` 连接表；直接官方登录时暂时管理官方地址覆盖及登录方式；设置模型压缩规则时，额外局部管理 `model_catalog_json`、`model_auto_compact_token_limit`、`model_context_window`，恢复时还原。
- 保留原生认证、MCP、skills、plugins、hooks、权限、项目、模型目录和历史；不改写会话数据库。
- 「恢复原连接」采用局部合并，接管期间新增的其他设置会保留；受管字段被外部修改时拒绝覆盖。「还原备份」则明确还原所选时刻的完整配置及文件认证，还原前状态也会保存。
- 上游密钥和官方凭据存入所选钥匙串或本地文件。官方刷新后的凭据先持久化再投入使用；存储不可用会明确失败并暂停该账号。
- 应用数据默认位于 `~/Library/Application Support/Codexpress`，目录权限 0700；源元数据、管理 socket、本地访问凭据和连接快照使用受限权限。
- `usage.sqlite` 只记录请求元数据及 Token；可关闭的原文缓存另存在 `history.sqlite`，不记录认证头。缓存输入 Token 是总输入的子集，总 Token 为输入 + 输出。
- 当前统计覆盖经过本地网关的流量；缺失或无法解析的 usage 标为不完整，可观察文字按字符估算。官方额度和重置卡属于当前客户端内部接口，接口变化时显示失败／陈旧缓存，不伪造余额。

## 聊天客户端接入

在「聊天客户端」使用独立本机入口，默认基址为 `http://127.0.0.1:17865/v1`。在聊天软件中选择 **OpenAI 兼容**供应商，填入页面显示的基址与「复制当前 Key」取得的密钥，随后获取模型列表。客户端若要求完整地址，分别填写 `/v1/chat/completions` 或 `/v1/responses`。应用同时接受不带 `/v1` 的对应路径，避免部分客户端自行拼接路径时重复配置。

此入口默认随网关启动，可修改端口、关闭接入、重新生成 Key 或设置 16–256 位不含空白的 ASCII Key。它与 Codex／SSH 的端口不同，Key 也不能复用本机网关、远端机器或当前来源密钥。更换 Key 后旧 Key 不能发起新请求；已提交的请求继续。配置文件 `chatbot-access.json` 在应用私有目录中以 0600 权限保存。上游真实凭据不会返回给聊天软件。

`GET /v1/models` 返回标准 `object: list` 和 `data[].id`，合并当前已启用、健康且符合路由设置的来源模型。固定来源模式只展示该来源；未缓存模型目录时按来源网络策略查询，并限制查询时间与并发。空列表表示当前没有可列出的来源，目录查询失败则返回明确错误，可在来源页刷新或手动填写模型 ID。

| `max_tokens`／`max_completion_tokens` | 映射为 `max_output_tokens`；两个设置冲突时拒绝。标准 Responses 小于 16 的正数预算提升至 16，以兼容探测请求 |
| 流式与非流式请求 | 上游统一请求 SSE；按客户端要求返回 Chat chunks、Responses 事件或完整 JSON。完整快照不重复计入已发送文本／工具参数 |
| 输入、输出、缓存与推理 Token | 使用上游完成事件中的计数，转换为对应协议的 usage；缺失计数不会伪造为已报告用量 |

官方 Codex 上游强制 `store: false` 与流式请求，保留加密推理续接所需的声明。不支持的采样参数、输出 Token 上限等从该来源的出站副本中移除；指定单个函数时，将工具集合限制到该函数，再使用 `required`，避免放宽调用范围。第三方 Responses 上游保留其扩展字段，不套用官方字段白名单。

第三方也可能转发至 Codex 后端。仅当其 HTTP 400 明确报告已知的参数校验拒绝时，同一来源最多修正三处并重试：不支持的参数、所需 instructions、store 值或已知工具选择类型。一般 400、网络超时、HTTP 5xx 和已开始输出的流不会触发这种重放。调整过的字段名称列在 `x-codexpress-adapted-parameters` 响应头，不包含参数值。

不支持将多候选 `n > 1`、非默认 stop／惩罚／logprobs／seed 参数或音视频输出无损映射到 Responses，遇到这些请求会返回 400，不静默省略其语义。普通函数工具由聊天客户端执行，网关不代替客户端执行工具。聊天客户端端口不提供文件上传或图片生成端点，生图请使用「图片生成」的独立入口；Responses 内置工具、文件 ID 的可用性仍取决于实际来源与模型。官方 `previous_response_id` 仅在完整本地缓存可恢复时展开历史，否则要求客户端发送完整上下文；关闭缓存后应使用完整历史请求。

客户端如能传递每条对话独立的 `thread-id`、`x-session-id` 或请求中的 `conversation_id`，网关会据此保持会话来源；未提供标识时不会凭相似内容猜测两次请求属于同一对话。不要为所有对话设置同一个固定会话 ID。

浏览器客户端可用此入口的 CORS 与 Bearer Key 认证，不使用 Cookie；浏览器或操作系统对网页访问本机网络的限制仍需由客户端满足。此端口只绑定 `127.0.0.1`，远端软件不能用该地址访问 Mac。请求沿用来源池优先级、逐源代理、会话接续与用量统计；即使 Codex 正在直接官方登录，聊天客户端仍可独立使用来源池。

协议依据：[OpenAI Responses 迁移指南](https://developers.openai.com/api/docs/guides/migrate-to-responses)、[流式事件指南](https://developers.openai.com/api/docs/guides/streaming-responses)和公开 Codex 客户端请求结构。

## SSH 远端接入

此功能将远端 Codex 连接到当前 Mac 上的来源池网关，不提供远端直接官方登录。SSH 只用于探测、验证和配置；后续推理请求直接通过网络访问 Mac，不随 SSH 连接转发。

1. **准备登录**：先在终端确认服务器主机指纹并完成密钥登录，例如 `ssh worker@server`。应用使用系统 `/usr/bin/ssh`、SSH 配置别名、ssh-agent 或指定私钥，强制检查已知主机，不接收密码、不自动接受陌生主机。远端需可通过 `python3` 启动 Python 3，首版支持 Linux／macOS 等 Unix 环境。
2. **填写连接**：打开「远端」会读取本地 `~/.ssh/config` 及静态 `Include`（支持相对路径、`~/`、绝对路径和通配路径），可在「从 SSH 配置选择」中选取明确的 `Host` 别名，配置更改后点击刷新。通配或否定的 Host 模式不列入菜单。选择后用户名、端口和私钥字段清空，沿用系统 SSH 的 `HostName`、`User`、`Port`、`IdentityFile`、`ProxyJump` 等设置；仍可手动覆盖。别名发现仅解析配置文本，不执行 `Match exec` 或代理命令；实际连接由系统 SSH 解析配置。也可手动填写服务器／SSH 别名，用户名单独填写。指定私钥需使用本机绝对路径，密钥若加密，应先在终端解锁。首次选择另一台机器会清空上一台的目录、地址及备份记录；若该别名已有保存记录，则载入对应机器的记录。
3. **探测目录和地址**：点击「连接并探测」，检查远端 `CODEX_HOME` 和登录用户的 `~/.codex`。没有找到时，手动填写已存在目录的绝对路径。默认本机地址取远端 `SSH_CONNECTION` 的客户端 IP；使用 NAT、ProxyJump 或端口转发时，这可能不是远端可反向连接的地址，可手动填写局域网、VPN IPv4 或解析到 IPv4 的主机名。
4. **确认共用端口**：远端与本机 Codex 共用网关端口（默认 `17863`），随网关启动，不需另行开启。网关监听 IPv4 网络接口；本机凭据仅接受来自回环地址的连接，远端须使用独立机器 Key 和预览中登记的地址。伪造 Host 或转发头不能获得本机权限；管理功能仍只通过本机私有 socket 提供。旧版本若使用独立远端端口（通常为 `17864`），需重新预览并应用一次；原始备份与机器 Key 保留。更改共用端口后，也需重新应用远端配置。
5. **预览与应用**：预览显示网关地址、认证方式、受影响的供应商 ID，以及本机已保存的模型压缩阈值和上下文窗口，不显示密钥或原配置里的敏感字段。先结束远端 Codex 正在运行的任务，再点击「备份并应用」。应用从远端直接检查网关身份和认证，不走代理、不跟随重定向；验证失败不会写入配置。预览后连接、模型规则、远端配置或来源模型目录若发生变化，会要求重新预览。
6. **重启与验证**：应用完成后手动重启远端 Codex；使用 VS Code 时重载对应的远端窗口，再继续对话，在本机「用量」查看请求。现有运行进程不会热更新，仅新建对话也不会重新加载模型目录；命令行、环境变量或项目级配置仍可能覆盖用户配置。

连接设置会切换根 `model_provider` 和 `model_providers.codexpress`，其 `base_url` 使用所填地址，`experimental_bearer_token` 使用独立远端 Key，并关闭该连接的官方认证要求和 WebSocket。原模型选择、MCP、工具及其他配置保留；根级旧官方地址覆盖和强制登录方式会移除。选择「同时接入已有自定义供应商 ID」时，除内置 OpenAI／Ollama／LM Studio 外的已有定义也会指向网关。旧对话的加密上下文仍受来源兼容限制，可能触发最终兜底。已选定的 `profile` 会阻止应用，避免档案覆盖导致切换不生效。

本机已保存逐模型压缩规则时，会读取远端原有自定义模型目录或 `models_cache.json` 中的模型元数据；文件不存在时使用随应用提供的目录。生成的远端专用文件为所选 Codex 目录下的 `.codexpress-model-catalog.json`，`model_catalog_json` 使用远端自己的绝对路径，不引用 Mac 上的文件。原有自定义目录和缓存只读，模型能力和指令元数据保留；未设置规则的模型保留远端原默认值。根级全局压缩阈值和上下文窗口会转入模型元数据后移除，以便逐模型规则生效。模型目录在 [Codex 启动时加载](https://developers.openai.com/codex/config-reference/)，应用后须重启远端 Codex，之后修改本机规则也需重新预览并应用。

没有本机规则且远端从未同步过规则时，保留远端压缩设置；清空本机规则后重新应用，会恢复首次同步压缩规则前的全局设置、目录引用和专用文件状态，同时继续使用网关。专用文件原来不存在时会删除；原来已有时恢复其原始字节。配置或专用文件不存在时，应用会创建所需文件；完整还原接入前设置时恢复其原内容或原本不存在的状态。所选 Codex 目录本身仍需已存在。

写入前，远端会在所选 Codex 目录的 `.codexpress-backups/` 下备份 `config.toml`、`auth.json`、`auth.json.bak`、专用模型目录和 `*.config.toml` 配置档案，同时记录文件原本缺失的状态。目录权限为 0700，备份、新配置与专用目录文件权限为 0600；`auth.json` 内容不会下载到本机，应用连接也不会改写它。远端配置与模型元数据只在内存中传给本机解析器，生成结果通过 SSH 标准输入发回，不放进进程参数或日志。目录、配置采用逐文件原子写入，普通写入失败尝试回滚，两份文件无法跨文件原子提交；操作前备份仍可恢复。对话数据库不读取、不修改。

「还原接入前设置」固定恢复此 Codex 目录**首次接入前**的配置、文件认证及专用模型目录，接入后自行修改的这些设置也会还原。重复应用仅新增操作前快照，不替换原始备份；还原前也会另存当前状态，连续点击还原始终回到原始设置，不会在网关配置之间切换。原始记录存放在远端 `.codexpress-backups/original.json`；旧版备份未包含模型目录时，使用首次同步压缩规则前另存的 `compaction-original.json` 记录补全其原始存在状态。即使本机仅记得最新快照，仍可在填写 SSH 连接和目录后还原。备份目录和恢复记录保留，对话文件不参与创建或清理。

升级前已应用过的机器，会检查远端最早的历史备份并验证所有记录文件的校验值。最早备份已含 Codexpress 标记、损坏、不完整或原始记录无效时，会拒绝将其他快照当作原始设置。识别采用保守规则，配置文字或注释中出现 Codexpress／远端 Key 前缀时也可能要求手动核对备份；应用不会猜测或自动删掉认证字段来拼造原始配置。原始备份丢失时，不能从当前网关配置反推出旧 URL 和密钥。

应用不会自动终止远端 Codex，请在还原前结束任务、还原后重启。「撤销 Key」使后续请求认证失败，不自动还原远端配置；重新预览可生成新 Key。远端不再有独立开关；要停用某台机器，请撤销它的 Key。

**网络要求**：当前远端入口为明文 HTTP，仅适合可信局域网或 VPN。SSH 加密覆盖配置操作，不覆盖后续 HTTP 推理；本功能不自动开通防火墙、路由器端口映射或 SSH 隧道，也不应直接暴露到公网。本机休眠、退出 Codexpress 或网络变化会使远端连接中断，需保持 Mac 和网关运行。SSH 操作超时若发生在应用或还原阶段，请重新读取配置核对状态，远端备份仍保留。

## 兼容范围

- Codex／SSH 入口使用原生 Responses HTTP/SSE，请求体与响应正文尽量按原字节转发。独立聊天客户端入口提供 Chat Completions／Responses 兼容转换；没有 Anthropic 协议转换。
- 第三方支持 `/responses`、`/responses/compact` 和 `/models` 路径；官方支持 Responses 生成／压缩、模型目录及认证／额度／重置卡链路。其他端点明确报错；实际可用能力取决于账号、模型与上游接口。
- 受管 provider 关闭 WebSocket，使用 SSE。工具是否受支持仍取决于上游模型与接口。
- 只覆盖系统代理模式；Clash TUN／透明代理关闭。应用不能凭一个网络选项绕过 TUN。
- `previous_response_id`、已识别密文／上游状态绑定原来源；完整可移植历史在原来源不可用时可迁移，成功后保持新来源。不会把生成到一半的结果拼接成另一来源的回复，也不会盲目重放结果不明的生成。
- 识别 Codex 的 `thread-id`／`session-id`，工具执行后的请求沿用已知来源；同一客户端的不同线程互相隔离。HTTP 及 `response.metadata` 中的路由标记原样转发，内部只存摘要，不受短响应 ID 的长度限制。
- 普通线程／模型偏好会持久保存；响应 ID、密文及路由标记的硬绑定仍在内存中。网关重启或绑定淘汰后，已确认的旧供应商仍能回到原来源；无法确认时按最终兜底规则处理，关闭兜底才保留 409。
- 已有自定义供应商 ID 的兼容连接须重新应用配置并重启 Codex 后生效。内置 OpenAI／Ollama／LM Studio ID 不会被改写；正常路径不将原源专属密文发往其他来源；最终兜底会明确降级并通知，且不修改本地历史。
- 压缩响应及超大单个观察事件仍按原字节转发，但 Token 采集可能不完整。

当前构建使用 ad-hoc 签名，尚未 Apple 公证。首次配置后，请确认模型列表、额度查询及新旧对话在所用账号和客户端上可用。

## 构建与检查

需要 Xcode/Swift 和 Rust stable。若项目内 `.tools/` 已安装 Rust，脚本会自动使用；否则使用 PATH 上的工具链。

```sh
bash scripts/check.sh
swift test
bash scripts/build.sh
```

完整工具续接的本地回归检查使用真实 Codex、临时配置目录及模拟上游，不访问真实账号：

```sh
python3 scripts/check-gateway-continuation.py
```

可用 `--codex /path/to/codex` 检查桌面端内置版本。

构建脚本编译 release Rust 和 Swift arm64，生成原生图标，打包并 ad-hoc 签名 `dist/Codexpress.app`。

开发时可通过 `CODEXPRESS_STATE_DIR` 指定隔离状态目录，通过 `CODEXPRESS_GATEWAY_PATH` 指定 helper。状态目录路径需足够短，满足 Unix socket 的系统路径长度限制。helper 启动参数：

```sh
codexpress-gateway --state-dir /absolute/private/path --port 17863
```

自动测试使用临时目录和本地模拟上游／代理，不消耗真实额度或重置卡。
